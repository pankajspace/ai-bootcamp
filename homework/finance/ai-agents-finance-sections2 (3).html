💡 Six levers that cut the bill
  • Tier models: big model to plan and write the final answer, small model for routing and summaries.
  • Compress context: summarise old turns instead of resending everything.
  • Prompt caching: keep the system prompt and tool definitions identical at the start of every call — cached input is billed at a 50–90% discount.

  • Cache in your app: don't fetch the same price twice (Section 4 does exactly this).

4.1Just-enough finance (five ideas, nothing more)

You don't need a finance degree to follow this code. You need these five ideas. Everything else is in an optional box below — glance at it, don't memorise it.

1 · Intrinsic value vs market priceA surveyor values a flat at ₹90 lakh; the owner asks ₹1.2 crore. The valuation is the intrinsic value, the asking price is the market price. Our system estimates the first and compares it with the second.
2 · The three financial statementsIncome statement = your yearly salary summary (earned, spent, left over). Balance sheet = a photo of today: what you own (flat, FD) and owe (home loan). Cash-flow statement = your bank passbook: real money in and out.
3 · Free cash flow (FCF)Salary minus household costs minus essential repairs = what you can actually save. For a company: cash from operations − spending on factories and equipment (capex). The single most important number in this project.
4 · DCF — money later is worth less₹100 next year is worth less than ₹100 today (you could have invested it). A DCF adds up all future FCF, converted to "today's money". That total is the intrinsic value.
5 · Peer comparisonIs ₹12,000 per sq ft expensive? Only compared with other flats in the same society. Same for stocks: compare Apple's price ratios with similar tech companies'.

4.3The financial tools (tools/financial_tools.py)

Every tool in the project follows three rules — once you see them, every tool reads the same way:

  1. Return a JSON string. The SDK hands tool results to the LLM as text; JSON keeps that text structured and unambiguous.
  2. Never crash. Delisted ticker? API limit? Catch the error and return {"error": ...} as JSON. The agent reads it and the pipeline carries on.
  3. Check the cache first. Two agents call the same tools. The first call fetches; the second gets the stored answer.

The small helpers every tool uses

The project ships its own helpers; these short versions behave the same way so you can read the tools without guessing:

Python · tools/financial_tools.py · helpers (simplified)
import json, math
import yfinance as yf
from agents import function_tool

class _SimpleCache:
    """Remembers tool results for this run, keyed by (tool name, ticker)."""
    def __init__(self):
        self._store = {}
    def get(self, key):
        return self._store.get(key)          # None = never seen this key
    def store(self, key, value):
        self._store[key] = value

_cache = _SimpleCache()

def _safe_float(v):
    """Anything → float, or None if it isn't a usable number."""
    try:
        f = float(v)
        return None if math.isnan(f) else f
    except (TypeError, ValueError):
        return None

def _millions(v):
    """Raw dollars → millions: 383285000000 → 383285.0"""
    f = _safe_float(v)
    return round(f / 1_000_000, 1) if f is not None else None

def _extract_row(df, *names, col):
    """Value of the first row name that exists in the table (in millions)."""
    for name in names:                       # e.g. try "Operating Income", then "EBIT"
        if name in df.index:
            return _millions(df.loc[name, col])
    return None
🧠 Why "fallback names"?

Yahoo doesn't label every company's rows identically — one company's "Operating Income" is another's "EBIT". _extract_row(fin, "Operating Income", "EBIT", col=col) is like asking "is Rahul here? If not, is R. Sharma here?" — it takes whichever name answers first.

Tool 1 · get_income_statement

Python · tools/financial_tools.py · get_income_statement
@function_tool
def get_income_statement(ticker: str) -> str:
    """
    Fetch the annual income statement for a given stock ticker.
    Returns revenue, gross profit, operating income, EBITDA, net income,
    and EPS for the last 4 fiscal years. All monetary values are in millions USD.

    Args:
        ticker: The stock ticker symbol, e.g. 'AAPL', 'MSFT', 'GOOGL'.
    """
    _key = ("get_income_statement", ticker.upper())          # ① cache key
    _hit = _cache.get(_key)
    if _hit is not None:
        return _hit                                            #    already fetched this run
    try:
        stock = yf.Ticker(ticker.upper())
        fin = stock.financials                                 # ② rows = line items, columns = fiscal years
        if fin is None or fin.empty:
            return json.dumps({"error": f"No income statement data found for {ticker}"})

        currency = stock.info.get("financialCurrency", "USD")
        result: dict = {
            "ticker": ticker.upper(),
            "company_name": stock.info.get("longName", ticker.upper()),
            "currency": currency,
            "unit": f"millions {currency}",
            "annual_data": {},                                 # ③ filled year by year
        }
        for col in fin.columns[:4]:                            #    the newest 4 fiscal years
            year = str(col.year)                               #    Timestamp('2025-09-30') → "2025"
            result["annual_data"][year] = {
                "revenue":          _extract_row(fin, "Total Revenue", col=col),
                "gross_profit":     _extract_row(fin, "Gross Profit", col=col),
                "operating_income": _extract_row(fin, "Operating Income", "EBIT", col=col),
                "ebitda":           _extract_row(fin, "EBITDA", col=col),
                "net_income":       _extract_row(fin, "Net Income", col=col),
                "r_and_d":          _extract_row(fin, "Research And Development", col=col),
            }

        info = stock.info                                      # ④ today's headline numbers
        result["eps_ttm"]       = _safe_float(info.get("trailingEps"))
        result["eps_forward"]   = _safe_float(info.get("forwardEps"))
        result["revenue_ttm_M"] = _millions(info.get("totalRevenue"))
        result["gross_margin_pct"] = _safe_float(info.get("grossMargins", 0)) and round(info.get("grossMargins", 0) * 100, 2)
        result["operating_margin_pct"] = round(info.get("operatingMargins", 0) * 100, 2) if info.get("operatingMargins") else None
        result["net_margin_pct"] = round(info.get("profitMargins", 0) * 100, 2) if info.get("profitMargins") else None

        output = json.dumps(result, indent=2, default=str)     # ⑤ dict → JSON text
        _cache.store(_key, output)                             #    remember it
        return output
    except Exception as e:
        return json.dumps({"error": str(e), "ticker": ticker}) # ⑥ never crash the pipeline
  1. Cache key ("get_income_statement", "AAPL") — a tuple of tool name + ticker, so different tools and tickers never collide.
  2. stock.financials is a pandas table: each row is a line item ("Total Revenue", "Net Income"…), each column is a fiscal-year end date, newest first. See the picture below.
  3. The loop turns that table into a nested dictionary keyed by year. col.year pulls the year out of the date.
  4. stock.info is a different source: one big dictionary of ready-made "right now" numbers (EPS, margins, price…).
  5. default=str tells json.dumps: "if you meet something you can't write as JSON (like a date), just turn it into text".
  6. Any failure becomes a JSON error message instead of an exception.

⚠️ The and trick on the gross-margin line

A and B in Python returns A if A is "empty" (0, None), otherwise B. So that line means "if there's a gross margin, give me it as a percent". It works — but when the field is missing it returns 0.0 (looks like a 0% margin!) while the next two lines return None. Prefer the clearer style of the next two lines: round(x * 100, 2) if x else None.

Tools 2 & 3 · get_balance_sheet and get_cash_flow_statement

Same skeleton as Tool 1 (cache → fetch → loop over 4 years → JSON → cache → return), different rows:

Balance sheet → per year

Total assets · total liabilities · shareholders' equity · cash · total and long-term debt · current assets and liabilities · goodwill & intangibles · working capital (current assets − current liabilities), plus market cap and book value per share.

Cash flow → per year

Operating cash flow · capex · investing and financing cash flow · dividends paid · share buybacks · free cash flow = operating cash flow − capex. FCF feeds the DCF later.

Small real-world catch: Yahoo reports capex as a negative number (money going out), so in code "OCF − capex" becomes ocf + capex_value. Always print one row and check the sign.

Some fields (R&D, goodwill, buybacks) aren't used in any formula — they're there so the LLM can talk about them. The four tools are independent: compute_key_ratios doesn't reuse the other three's output; it fetches its own.

Python · tools/financial_tools.py · compute_key_ratios
@function_tool
def compute_key_ratios(ticker: str) -> str:
    """
    Compute key fundamental ratios for a given stock ticker.
    Calculates valuation ratios (P/E, P/B, P/S, EV/EBITDA), profitability
    ratios (ROE, ROA, net margin), leverage ratios (Debt/Equity, current ratio,
    quick ratio), and growth metrics (revenue YoY, EPS YoY).

    Args:
        ticker: The stock ticker symbol, e.g. 'AAPL', 'MSFT', 'GOOGL'.
    """
    _key = ("compute_key_ratios", ticker.upper())
    _hit = _cache.get(_key)
    if _hit is not None:
        return _hit
    try:
        stock = yf.Ticker(ticker.upper())
        info = stock.info                                    # one big dict of ready-made fields

        def pct(v):                                          # 0.4691 → 46.91
            return round(v * 100, 2) if v is not None else None

        # --- Valuation ---
        pe_trailing = _safe_float(info.get("trailingPE"))
        pe_forward  = _safe_float(info.get("forwardPE"))
        pb_ratio    = _safe_float(info.get("priceToBook"))
        ps_ratio    = _safe_float(info.get("priceToSalesTrailing12Months"))
        ev_ebitda   = _safe_float(info.get("enterpriseToEbitda"))
        ev_revenue  = _safe_float(info.get("enterpriseToRevenue"))

        # --- Profitability ---
        roe          = pct(info.get("returnOnEquity"))
        roa          = pct(info.get("returnOnAssets"))
        net_margin   = pct(info.get("profitMargins"))
        gross_margin = pct(info.get("grossMargins"))
        op_margin    = pct(info.get("operatingMargins"))

        # --- Liquidity & leverage ---
        current_ratio = _safe_float(info.get("currentRatio"))
        quick_ratio   = _safe_float(info.get("quickRatio"))
        debt_to_eq    = _safe_float(info.get("debtToEquity"))   # already in %

        # --- Growth: worked out by hand from the income statement ---
        fin = stock.financials
        revenue_growth = None
        if fin is not None and not fin.empty and len(fin.columns) >= 2:
            rev_rows = [r for r in ["Total Revenue"] if r in fin.index]
            if rev_rows:
                rev_now  = fin.loc[rev_rows[0], fin.columns[0]]   # column 0 = newest year
                rev_prev = fin.loc[rev_rows[0], fin.columns[1]]   # column 1 = the year before
                if rev_prev and float(rev_prev) != 0:
                    revenue_growth = round(((float(rev_now) - float(rev_prev)) / abs(float(rev_prev))) * 100, 2)

        # --- Free-cash-flow yield ---
        market_cap = info.get("marketCap")
        fcf        = info.get("freeCashflow")
        fcf_yield  = None
        if market_cap and fcf and float(market_cap) > 0:
            fcf_yield = round((float(fcf) / float(market_cap)) * 100, 2)

        # --- Dividend ---
        div_yield  = pct(info.get("dividendYield"))

4.4The valuation tools (tools/valuation_tools.py)

Two ways of answering "is this stock cheap?" — and the clever part is that they disagree for different reasons.

🧠 DCF = the surveyor

Values the flat on its own merits: how much rent will it earn for years to come, in today's money? Ignores what the neighbours sold for.

🧠 Peers = the property dealer

"Flats in this society go for ₹11,000 per sq ft; this one wants ₹15,000." Ignores the future; only compares prices right now.

Tool 1 · run_dcf_model — four steps

  1. Project free cash flow for 5 years, growing at growth_rate (default 8%).
  2. Discount each year back to today's money at discount_rate (default 9%) — the return investors demand for the risk.
  3. Terminal value: everything after year 5 as one lump, growing forever at terminal_growth_rate (max 3%), also discounted back.
  4. Per share: add it all up (= value of the business), subtract net debt (debt − cash), divide by the number of shares. Compare with today's price → upside % → verdict.

@function_tool
def run_dcf_model(ticker: str, growth_rate: float, discount_rate: float,
                  terminal_growth_rate: float) -> str:
    """Estimate intrinsic value per share with a 5-year DCF and compare it to the current price."""
    try:
        # The real tool reads these from yfinance: latest FCF, total debt, cash, shares, price
        fcf, net_debt, shares, price = _load_dcf_inputs(ticker)

        # Step 1 · project free cash flow for 5 years
        fcfs = [fcf * (1 + growth_rate) ** t for t in range(1, 6)]
        # Step 2 · bring each year back to today's money
        pv_fcfs = [f / (1 + discount_rate) ** t for t, f in enumerate(fcfs, start=1)]
        # Step 3 · everything after year 5 as one lump (Gordon growth), also brought back
        terminal_value = fcfs[-1] * (1 + terminal_growth_rate) / (discount_rate - terminal_growth_rate)
        pv_terminal = terminal_value / (1 + discount_rate) ** 5
        # Step 4 · business value → owners' value → per share
        enterprise_value = sum(pv_fcfs) + pv_terminal
        equity_value = enterprise_value - net_debt
        intrinsic_value = equity_value / shares

        upside = (intrinsic_value / price - 1) * 100
        return json.dumps({"intrinsic_value": round(intrinsic_value, 2), "current_price": price,
                           "upside_pct": round(upside, 1), "verdict": _dcf_verdict(upside)})
    except Exception as e:
        return json.dumps({"error": str(e), "ticker": ticker})

def _dcf_verdict(upside):
    if upside > 30:   return "SIGNIFICANTLY UNDERVALUED"
    if upside > 15:   return "SLIGHTLY UNDERVALUED"
    if upside >= -15: return "FAIRLY VALUED"
    if upside >= -30: return "SLIGHTLY OVERVALUED"
    return "SIGNIFICANTLY OVERVALUED"
  1. (1 + growth_rate) ** t — ** means "to the power of". Year 3 at 8% growth: fcf × 1.08³.
  2. enumerate(fcfs, start=1) gives pairs (1, year-1 FCF), (2, year-2 FCF)… so each year is divided by (1 + rate) to the power of its own year number.
  3. The terminal formula divides by discount_rate − terminal_growth_rate. If they get close, the value explodes — that's why the agent is told "never above 3%".
  4. The verdict is computed in code, from fixed thresholds, so it's the same every time. (Section 4.8 explains why that matters.)

Python · _peer_verdict · simplified sketch
WEIGHTS = {"forward_pe": 0.30, "ev_ebitda": 0.25, "pe": 0.20, "ps": 0.15, "pb": 0.10}

def _peer_verdict(subject, peer_avg):
    total, weight_used = 0.0, 0.0
    for key, w in WEIGHTS.items():
        s, p = subject.get(key), peer_avg.get(key)
        if s is None or not p:                     # missing on either side → skip this multiple
            continue
        total += w * (s / p - 1) * 100             # premium of this multiple, times its weight
        weight_used += w
    if weight_used == 0:
        return "N/A", None
    weighted_avg = round(total / weight_used, 1)   # re-scale so skipped weights don't count
    if weighted_avg > 30:     verdict = "SIGNIFICANTLY OVERVALUED"
    elif weighted_avg > 15:   verdict = "SLIGHTLY OVERVALUED"
    elif weighted_avg >= -15: verdict = "FAIRLY VALUED"
    elif weighted_avg >= -30: verdict = "SLIGHTLY UNDERVALUED"
    else:                     verdict = "SIGNIFICANTLY UNDERVALUED"
    return verdict, weighted_avg
💰 Why those weights?

Forward P/E 30% — what professional investors look at most. EV/EBITDA 25% — fair across companies with different debt; the standard in M&A. Trailing P/E 20% — real reported profits, not forecasts. P/S 15% — still works when profits are tiny. P/B 10% — book value says little about brand- and software-heavy companies.

Python · _score_headline · simplified sketch (illustrative keyword lists)
import re

BULLISH_SIGNALS = ["beat", "beats", "record", "surge", "upgrade", "growth", "strong",
                   "raises", "buyback", "outperform", "jumps", "rally", "gains", "boosts"]
BEARISH_SIGNALS = ["miss", "misses", "fall", "falls", "drop", "decline", "cut", "downgrade",
                   "lawsuit", "probe", "investigation", "antitrust", "recall", "fine", "weak", "loss"]

def _score_headline(text: str):
    words = re.findall(r"[a-z]+", text.lower())          # "Apple beats estimates!" → ["apple", "beats", "estimates"]
    bull = sum(w in BULLISH_SIGNALS for w in words)       # True counts as 1
    bear = sum(w in BEARISH_SIGNALS for w in words)
    if bull + bear == 0:
        return "neutral", 0.0                             # no signal words at all
    net = (bull - bear) / (bull + bear)                   # always between -1 and +1
    if net > 0.15:  return "bullish", round(net, 2)
    if net < -0.15: return "bearish", round(net, 2)
    return "neutral", round(net, 2)

Net score = (bullish words − bearish words) ÷ (bullish + bearish). Two good words and none bad → +1.0. One of each → 0. It's crude — but fast, free, and it catches the strongest signals. The LLM does the subtle reading later.

Every agent is the same three lines of SDK code — Agent(name, instructions, tools, model). All the intelligence is in the instructions. So read each agent as a prompt-engineering lesson. Five tricks repeat across all of them:

⑤ If-then decision rules"Raise the discount rate only if debt/equity > 3.0× AND cash flow is declining." Business logic, written in English.

than ten generic "stock rises" headlines.
"""

news_sentiment_agent = Agent(
    name="NewsAndSentimentAgent",
    instructions=NEWS_SENTIMENT_INSTRUCTIONS,
    tools=[search_recent_news, analyze_sentiment],
    model="gpt-4o",
)
  1. A tool chain through the LLM: step 2 says "call analyze_sentiment with the JSON output from step 1". The LLM copies tool 1's result into tool 2's argument — tools never talk directly.
  2. RAW NEWS SOURCES is mandatory — every claim must be checkable with a link. Same principle as the verified-news agent in Section 2.
  3. "Signal over noise" is the line a real news-desk head would say. Putting it in the prompt makes the agent rank, not just list.

from agents import Agent
from fundamental_analysis_agent.tools.financial_tools import get_balance_sheet, compute_key_ratios
from fundamental_analysis_agent.tools.news_tools import search_recent_news

RISK_INSTRUCTIONS = """
You are a risk analyst at a hedge fund. Your job is to stress-test investment
theses and find the vulnerabilities that optimistic analysts overlook.
You are deliberately skeptical. Your goal is NOT to be bearish for its own sake,
but to identify REAL, MATERIAL risks that an investor must weigh.

Steps to follow:
1. CALL get_balance_sheet(ticker) -- examine debt levels, cash runway,
   working capital. A company burning cash with high debt is a red flag.
2. CALL compute_key_ratios(ticker) -- focus on:
   - Debt/Equity: >2.0 is high leverage territory
   - Current Ratio: <1.0 means current liabilities exceed current assets
   - Interest Coverage: implied from operating income / interest expense
   - P/E vs growth: if P/E is high but growth is slowing, valuation risk is elevated
3. CALL search_recent_news(ticker, max_results=10) -- scan for:
   regulatory investigations, lawsuits, data breaches, product recalls,
   management changes, covenant violations, credit downgrades.
4. WRITE A STRUCTURED RISK REPORT:
   RISK REGISTER (table format):
     | Risk | Category | Severity | Evidence |
     Categories: [FINANCIAL | OPERATIONAL | REGULATORY | MARKET | MACRO]
     Severity: [LOW | MEDIUM | HIGH | CRITICAL]
   FINANCIAL STRESS TEST:
     - What happens to the company if revenue drops 20%?
     - Can it service its debt with current cash flow?
     - What is the cash runway (months of expenses covered by cash)?
   KEY VULNERABILITIES: Top 3 specific risks with detailed explanation.
   RISK VERDICT: One of [LOW RISK | MODERATE RISK | ELEVATED RISK | HIGH RISK]
     with a 2-sentence justification.

Be specific and evidence-based. Vague risks like "macroeconomic uncertainty"
only add value if you connect them to specific company vulnerabilities.
"""

risk_agent = Agent(
    name="RiskAgent",
    instructions=RISK_INSTRUCTIONS,
    tools=[get_balance_sheet, compute_key_ratios, search_recent_news],
    model="gpt-4o",
)
  1. Same data, different eyes. It borrows two tools from the FinancialDataAgent and one from the news agent. The data is identical; the job is to find what could go wrong. (And thanks to the cache, those calls cost nothing extra.)
  2. "Sceptical, NOT bearish for its own sake" — without the second half, an adversarial agent finds doom everywhere.
  3. A stress test in three questions: revenue −20%? can it pay its debt? how many months of cash? This is what a risk manager actually asks.
  4. "Vague risks only count if connected" — kills filler like "macroeconomic uncertainty".
💰 Two risk words, in plain English

Cash runway = how many months the company could pay its bills from the cash it has, if no new money came in. Covenant violation = breaking a promise written into a loan ("we'll keep debt below 3× earnings"). It can let the lender demand money back early.

ValuationAgent — rules for choosing assumptions

from agents import Agent
from fundamental_analysis_agent.tools.valuation_tools import run_dcf_model, get_peer_multiples

VALUATION_INSTRUCTIONS = """
You are a buy-side equity analyst specializing in company valuation.

Your job:
Estimate the intrinsic value of a stock using two complementary methods,
then synthesize them into a clear investment verdict.

Steps to follow:
1. DETERMINE DCF INPUTS
   Your input starts with "Ticker: [SYMBOL]" -- use that symbol for all tool calls.
   It also contains a ---FINANCIAL CONTEXT FOR DCF--- block extracted by the
   Orchestrator from the financial data agent. Read it before choosing inputs.

   BASELINE (apply by default):
   - growth_rate:          0.08 (8%) -- use unless FCF 3-year CAGR differs by more than 3pp
   - discount_rate:        0.09 (9%) -- use for large-cap, investment-grade companies
   - terminal_growth_rate: 0.03 (3%) -- use for stable, mature companies

   ALLOWED ADJUSTMENTS (document the reason explicitly, citing the value from the context block):
   - Raise discount_rate to 0.10-0.12 only if debt/equity ratio > 3.0x
     AND operating cash flow trend = declining.
   - Adjust growth_rate toward the FCF 3-year CAGR if it differs from 8% by more than 3pp.
   - Lower growth_rate below 0.06 only if both revenue growth YoY values are negative.
   - Never set terminal_growth_rate above 0.03.
   Always output a DCF INPUTS section listing your chosen values and the reason
   (either "baseline -- no adjustment triggered" or the specific data point that triggered a change).

2. CALL run_dcf_model(ticker, growth_rate, discount_rate, terminal_growth_rate)
   Interpret the result: upside/downside %, whether the stock is cheap or expensive.

3. CALL get_peer_multiples(ticker)
   Compare the company's P/E, EV/EBITDA, P/B vs sector peers.
   Note whether the premium/discount is justified by superior growth or margins.

4. SYNTHESIZE: Write a structured valuation report with these sections:
   - DCF INPUTS: chosen values and, for each, "baseline" or the data point that triggered a change.
   - DCF VALUATION: Intrinsic value per share, upside/downside,
     and the verdict field returned by run_dcf_model exactly as-is.
   - RELATIVE VALUATION: How the stock trades vs peers. The peer_verdict field in the
     get_peer_multiples result already contains the weighted average premium and
     computed verdict -- report it exactly as returned. Do not override or reinterpret it.
   - VALUATION VERDICT: Synthesize the DCF verdict and the peer-based verdict into a
     single final verdict using the same 5-level scale.
     Use the more conservative (more cautious) of the two if they differ.
   - CONFIDENCE LEVEL: Derive from method agreement:
       HIGH   -- both DCF verdict and peer verdict are the same label
       MEDIUM -- they differ by one level (e.g., SLIGHTLY vs SIGNIFICANTLY)
       LOW    -- they diverge by more than one level or point in opposite directions
   - KEY ASSUMPTIONS & RISKS: What could make the DCF wrong?
"""

valuation_agent = Agent(
    name="ValuationAgent",
    instructions=VALUATION_INSTRUCTIONS,
    tools=[run_dcf_model, get_peer_multiples],
    model="gpt-4o",
)
  1. The LLM picks the DCF inputs — but inside a fence. Baseline 8 / 9 / 3, and only listed triggers may change them. It must cite the number that triggered a change. Creativity where it helps, rules where it matters.
  2. "Report it exactly as returned" — the tool already computed the verdicts; the LLM only relays them.
  3. "More conservative of the two" — when the surveyor and the dealer disagree, believe the more cautious one. Try it below.
💰 CAGR and "pp" in one breath

CAGR (compound annual growth rate) = the steady yearly growth that would take you from the start value to the end value. pp = percentage points: going from 8% to 11% is +3 pp (not +3%).

OrchestratorAgent — the director of research

Python · agents/orchestrator.py
from agents import Agent
from fundamental_analysis_agent.agents.financial_data_agent import financial_data_agent
from fundamental_analysis_agent.agents.valuation_agent import valuation_agent
from fundamental_analysis_agent.agents.news_sentiment_agent import news_sentiment_agent
from fundamental_analysis_agent.agents.risk_agent import risk_agent
from fundamental_analysis_agent.agents.report_writer_agent import report_writer_agent

ORCHESTRATOR_INSTRUCTIONS = """
You are a senior investment analyst orchestrating a full fundamental analysis.
You coordinate a team of specialist sub-agents and synthesize their findings
into a final investment brief.

Given a stock ticker symbol, execute the following workflow:

PHASE 1 -- DATA GATHERING (call all three simultaneously in a single step):
Call financial_data_analysis, news_and_sentiment_analysis, and risk_assessment
all at once with the ticker. Do not wait for one to finish before calling the next.
They are independent and must be issued as parallel tool calls in a single response.
- financial_data_analysis:     returns financial statements, key ratios, and a financial health verdict.
- news_and_sentiment_analysis: returns recent news, sentiment score, and risk flags.
- risk_assessment:             returns a risk register and financial stress test.

PHASE 2 -- VALUATION (requires Phase 1 financial data):
Step 2: Call valuation_analysis with the following input (fill in the values
from the Step 1a output). The ticker must appear on the first line.
    Ticker: [TICKER]
    ---FINANCIAL CONTEXT FOR DCF---
    Revenue growth YoY (latest year): [X%]
    Revenue growth YoY (prior year):  [X%]
    FCF 3-year CAGR (if available):   [X%]
    Debt/Equity ratio:                [X]
    Operating cash flow trend:        [growing | declining | stable]
    ---END FINANCIAL CONTEXT---
If a value is not available in the Step 1a output, write "N/A".

PHASE 3 -- SYNTHESIS:
Step 3: Call write_investment_report with ALL findings from Steps 1a, 1b, 1c, and 2.
Structure your input as:
    FINANCIAL DATA ANALYSIS:   [output from step 1a]
    NEWS & SENTIMENT ANALYSIS: [output from step 1b]
    RISK ASSESSMENT:           [output from step 1c]
    VALUATION ANALYSIS:        [output from step 2]

IMPORTANT:
- Do not skip any step. All four specialist analyses are required.
- If a sub-agent returns an error for any tool, note it in the final report
  rather than stopping the workflow entirely.
- Your final output must be the ReportWriterAgent's output copied verbatim,
  character for character. Do not add commentary, remove sections, reformat,
  or summarize any part of it.
- Be patient: the workflow has multiple API calls and may take 30-60 seconds.
"""

orchestrator = Agent(
    name="OrchestratorAgent",
    instructions=ORCHESTRATOR_INSTRUCTIONS,
    tools=[
        financial_data_agent.as_tool(
            tool_name="financial_data_analysis",
            tool_description=(
                "Fetches and analyzes financial statements (income statement, "
                "balance sheet, cash flow) and computes key fundamental ratios "
                "for a given stock ticker. Returns a financial health verdict."
            ),
        ),
        news_sentiment_agent.as_tool(
            tool_name="news_and_sentiment_analysis",
            tool_description=(
                "Retrieves recent news headlines and performs sentiment analysis "
                "for a given stock ticker. Returns sentiment verdict, key themes, "
                "and any material risk flags from news."
            ),
        ),
        risk_agent.as_tool(
            tool_name="risk_assessment",
            tool_description=(
                "Performs a comprehensive risk assessment for a given stock ticker. "
                "Examines balance sheet stress points, leverage ratios, liquidity, "
                "and news-based risk events. Returns a risk register and verdict."
            ),
        ),
        valuation_agent.as_tool(
            tool_name="valuation_analysis",
            tool_description=(
                "Estimates the intrinsic value of a stock using DCF modeling and "
                "peer multiples comparison. Returns intrinsic value per share, "
                "upside/downside percentage, and a valuation verdict."
            ),
        ),
        report_writer_agent.as_tool(
            tool_name="write_investment_report",
            tool_description=(
                "Synthesizes all analysis (financial data, valuation, sentiment, risk) "
                "into a final, professional investment brief. Takes the combined "
                "findings from all specialist agents and produces the final report."
            ),
        ),
    ],
    model="gpt-4o",
)
  1. .as_tool(tool_name=…, tool_description=…) wraps a whole agent — its instructions, its tools, its model — into one function the orchestrator can call by name. To the orchestrator, valuation_analysis(...) looks no different from run_dcf_model(...).
  2. The tool name and description are what the orchestrator's LLM reads when deciding what to call. They're mini-prompts — write them like job descriptions.
  3. The FINANCIAL CONTEXT block is a hand-off form. The orchestrator copies five numbers from the financial agent's report into it. The valuation agent's rules ("if debt/equity > 3.0×…") read exactly these lines.
  4. "Copy verbatim, character for character" — otherwise the orchestrator likes to "helpfully" summarise the final brief and drop sections.
  5. "Note errors, don't stop" — one failed news call shouldn't kill a whole analysis.
🧠 Why agents-as-tools here, not handoffs?

A handoff is transferring a customer's call to another department — you're off the line. An agent-as-tool is the manager phoning three specialists, staying on the line, collecting their answers, and then deciding what to send to the next person. The orchestrator must collect four reports and pass the right pieces on, so it can't hang up. Bonus: tool calls can run in parallel, handoffs can't.

4.8Behind the scenes: 7 bugs and their fixes

This is the most valuable part of the project for engineers — every one of these will happen in your own agent systems.

1 · Don't let the LLM classify numbers it didn't computeThe valuation agent used to turn raw peer premiums (+16.2%, +242.7%…) into a verdict itself, and got it inconsistently. Fix: _peer_verdict computes it in the tool; the agent relays it. If code can compute it, code should.
2 · Rules after the output get ignoredThe writer gave wrong ratings even with the table in the prompt — the table was at the bottom, but the rating is written near the top. Fix: move the table and the "derivation" step to the top of the prompt.
3 · Keep sections self-containedCash-flow facts leaked into the balance-sheet section: technically true, hard to audit. Fix: one instruction — each section uses only its own data.
4 · LLMs add opinions nobody sourced"Enhances shareholder value." "Premium not justified by growth" — contradicting the valuation agent. Fix: data-backed statements only; relay upstream verdicts verbatim.
5 · Shared tools double the API callsFinancial and Risk agents both fetched the same balance sheet. Fix: a small in-memory cache inside each tool. Agents didn't change at all.
6 · Parallel must be verified, not assumedThe SDK runs calls together only if the LLM issues them together. Fix: a --trace flag; three CALLs before any OUTPUT = parallel.
7 · Write the reasoning steps into the promptValuation justifies each assumption, the orchestrator follows numbered phases, the writer shows its derivation. Here chain-of-thought isn't decoration — it's what makes the behaviour correct.
💡 The one-sentence summary for learners

Push anything deterministic into tools (Python), and let the LLM reason only over verified inputs. Plus the two bonus bugs you found on this page: the debt/equity unit trap (4.3) and the "refines" substring false alarm (4.5).

4.9Humans vs agents, and what to build next

Agents do

Collect and structure data · compute ratios · read statements · scan news at scale · apply valuation models the same way every time · check against risk rules — with every number traceable to a tool call.

Humans still do

Validate the assumptions (a DCF is only as good as its growth and discount rates) · settle conflicts (bullish news vs "too expensive") · judge what's hard to measure: management, moats, regulation · own the decision — investing is regulated and fiduciary.

The skill that matters isn't competing with agents at what they automate — it's knowing when to trust them, when to question them, and when to override them.

💡 Homework: five extensions
  • Memory: save every brief to SQLite and add a HistoricalComparisonAgent — "what changed since last quarter?" (Section 2's episodic memory, reused.)
  • Human approval of DCF assumptions: pause before valuation and let the analyst confirm or change growth and discount rates.
  • PortfolioAgent: analyse a watchlist and rank stocks on valuation, quality and sentiment.
  • Better data: swap yfinance for Financial Modeling Prep or Polygon.io — only the tools change, the agents stay the same.
  • Web app: a FastAPI backend plus a Streamlit or React front end that streams each agent's progress.

Wrap-up

What to remember

  1. Frameworks all do the basics; remember one superpower each. Production = OpenAI SDK · flexibility = LangGraph · scale = ADK · roles = CrewAI · conversation = AutoGen · schema = PydanticAI · sovereignty = Mistral · code = smolagents · screens = Claude SDK · documents = LlamaIndex.
  2. Architecture is a cost decision. The same task cost 10× more tokens as a "meeting" of agents.
  3. Tools are the hands, agents the brains, the orchestrator the manager. Read the project bottom-up.
  4. Three phases: independent work in parallel → dependent work next → synthesis last.
  5. Verdicts come from code and tables, not moods: DCF thresholds, weighted peer premium, the 5×4 rating table.
  6. Watch units, signs and substrings. Debt/equity in %, negative capex, "refines".
