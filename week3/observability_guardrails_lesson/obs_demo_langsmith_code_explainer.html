The personality bot: caching plus full observability with LangSmith

Type a famous person's name and the bot answers in two lines. Repeated questions are answered from a cache for free, and every step of every question is recorded in LangSmith, so you can see exactly what happened, how long it took and what it cost.

What it does, in one minute

💡 The story

The script asks seven questions in a row:

#QuestionWhat happensCost
1Elon MuskNew question → ask OpenAI, save the answera tiny bit
2Elon MuskExact same text → reuse the saved answerfree
3Who is Elon Musk?Different words, same meaning → reuse the saved answeralmost free
4Marie CurieNew → ask OpenAIa tiny bit
5"  marie curie "Same text after cleaning (lower case, extra spaces removed) → exact hitfree
6Tell me about Marie CurieSame meaning → semantic hitalmost free
7Albert EinsteinNew → ask OpenAIa tiny bit

Seven questions, only three paid model calls. And for every question, LangSmith keeps a trace: a step-by-step record you can open in the browser.

🍛 Analogy: the chai stall that keeps a notebook

A busy chai stall gets the same orders all day. The owner writes each new order and its recipe in a notebook (cache). "One cutting chai" again? Read it from the notebook (exact hit). "Half a glass of tea, please"? Different words, same thing (semantic hit). And a CCTV camera records every order from start to finish (tracing), so when a customer complains you can rewind and see exactly what happened.

How to run it

⌨️ Setup (5 minutes)

  1. Put obs_demo_langsmith.py, requirements.txt and .env.example in one folder.
  2. Install: pip install -r requirements.txt (Python 3.10+).
  3. Create a free LangSmith account at smith.langchain.com → Settings → API Keys → create a key.
  4. Copy .env.example to .env and fill in both keys: 
    OPENAI_API_KEY=sk-...
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=lsv2_...
LANGSMITH_PROJECT=observability_demo
  5. Run: python obs_demo_langsmith.py
  6. Open smith.langchain.com → Tracing Projects → observability_demo. You'll see seven personality_query runs, one per question.

What changed from the original, and why

Same idea, same three checkpoints, same seven-question demo. Here's everything that's different.

#OriginalNowWhy
1gpt-3.5-turbo with its old pricesgpt-6-luna, prices $0.10 / $0.50 per million tokensOpenAI shut gpt-3.5-turbo down in October 2026, so every call failed. gpt-6-luna is OpenAI's current small, cheap model.
2Keys copied into os.environ in code, using the old LANGCHAIN_* namesAll settings in .env with the current LANGSMITH_* namesThe old lines crashed with a TypeError whenever a key was missing. Settings belong in .env, not in code.
3langsmith.run_helpers and tracing_v2_enabled()from langsmith import traceable; tracing switched on by LANGSMITH_TRACING=trueThe current, simpler way.
4Prompts and answers not recordedclient = wrap_openai(OpenAI())One line adds the logs pillar: every prompt, answer, model and token count appears in the trace.
5Every node always ran; each one checked "already answered? then do nothing"Two small routers send the question straight to END on a hitThe trace now shows only the steps that really happened, which makes it easier to read.
6@traceable on every graph nodeRemoved from the nodesLangGraph already traces every node; the extra decorator created duplicate steps.
7Similarity threshold 0.85; test questions "Tell me about Elon", "Info on Curie"Threshold 0.70; "Who is Elon Musk?", "Tell me about Marie Curie"With OpenAI's current embedding model, short rewordings usually score below 0.85, so the demo's "semantic hits" didn't happen. 0.70 shows the idea; tune it on your own data.
8API errors returned the text "Error: …" as the answerErrors are not caughtThe original saved the error message in the cache and served it as the answer forever after. Now the error shows up red in the trace and nothing bad is cached.
9scikit-learn's cosine_similaritynp.dotOpenAI's embedding vectors already have length 1, so a dot product is the cosine similarity. One less heavy library to install.
10"⚡ EXACT CACHE HIT:" glued to the front of the answerThe answer stays clean; the hit type is a separate fieldA field you can filter and count is a metric; text glued to an answer is not.
11lower().strip()clean() also squeezes repeated spaces"marie  curie" and "marie curie" should be the same question.
12time.sleep(1) between questionsRemovedIt only made the demo slower.

Imports and settings

obs_demo_langsmith.py · lines 35–57
import time
from typing import TypedDict

import numpy as np
from dotenv import load_dotenv
from langgraph.graph import StateGraph, END
from langsmith import traceable
from langsmith.wrappers import wrap_openai
from openai import OpenAI

load_dotenv()   # reads OPENAI_API_KEY and the LANGSMITH_* settings from .env

CHAT_MODEL = "gpt-6-luna"                    # OpenAI's small, fast, cheap model
EMBEDDING_MODEL = "text-embedding-3-small"   # turns text into a list of numbers (a vector)

# Prices in US$ per 1 million tokens (check OpenAI's pricing page, they change)
PRICE_INPUT, PRICE_OUTPUT, PRICE_EMBEDDING = 0.10, 0.50, 0.02

SIMILARITY_THRESHOLD = 0.70   # how close (0 to 1) a new question must be to reuse an old answer

# wrap_openai: one line, and every OpenAI call (prompt, answer, model, tokens, time)
# is logged to LangSmith automatically.
client = wrap_openai(OpenAI())

💡 What each part is for

  • numpy: maths on the embedding vectors (the dot product).
  • langgraph: builds the three-checkpoint graph.
  • traceable: a decorator that turns any Python function into a step (span) in the trace.
  • wrap_openai: wraps the OpenAI client so every chat call is logged automatically.
  • Two models: gpt-6-luna writes answers; text-embedding-3-small turns text into a list of numbers that captures its meaning.
  • Prices: used to compute the cost metric. Prices change, so they're kept in one easy-to-edit line.
  • SIMILARITY_THRESHOLD: how alike two questions must be (0 to 1) before we reuse an answer.

🍛 Analogy: wrap_openai

Like putting a call recorder on the office phone. You don't change how anyone talks; every call is simply recorded with its time and length.

The State: what the graph knows about one question

obs_demo_langsmith.py · lines 63–69
class AgentState(TypedDict, total=False):
    query: str            # the question, e.g. "Elon Musk"
    response: str         # the answer
    cache_hit_type: str   # "exact", "semantic", "fresh" (or "miss" while still looking)
    similarity: float     # best similarity score found in the semantic cache
    cost: float           # US$ spent on the LLM for this question
    tokens: int           # LLM tokens used for this question
obs_demo_langsmith.py · lines 72–74
def clean(text: str) -> str:
    """'  Marie Curie ' and 'marie curie' should count as the same question."""
    return " ".join(text.lower().split())

💡 In plain words

The State is a small dictionary that travels through the graph. Each node reads it and returns only the fields it wants to change; LangGraph merges them in. total=False means a field can be missing until a node fills it in.

clean() makes the cache forgiving: " Marie Curie " → "marie curie".

🍛 Analogy

A token slip at a food court: it starts with just your order, and each counter writes on it ("not in fridge", "cooked fresh", "₹2 gas used") until it comes back to you.

Two caches. cache maps a cleaned question to its answer. embeddings maps the same question to its meaning vector, for the semantic search.

2a · get_embedding: text → meaning vector

obs_demo_langsmith.py · lines 85–90
    @traceable(name="get_embedding", run_type="embedding")
    def get_embedding(self, text: str) -> np.ndarray:
        response = client.embeddings.create(model=EMBEDDING_MODEL, input=text)
        tokens = response.usage.total_tokens
        print(f"   [metric] embedding: {tokens} tokens, ${tokens / 1e6 * PRICE_EMBEDDING:.7f}")
        return np.array(response.data[0].embedding)

Sends the text to OpenAI's embedding model and gets back 1,536 numbers. Texts with similar meaning get similar numbers. It also prints a metric line: tokens and cost. Embeddings are extremely cheap: about $0.0000001 for a short question.

2b · find_semantic_match: the closest earlier question

obs_demo_langsmith.py · lines 92–104
    @traceable(name="find_semantic_match", run_type="tool")
    def find_semantic_match(self, query: str):
        """Return (closest saved question, similarity score)."""
        if not self.embeddings:
            return None, 0.0
        query_vector = self.get_embedding(clean(query))
        best_key, best_score = None, -1.0          # start below any real score
        for key, vector in self.embeddings.items():
            score = float(np.dot(query_vector, vector))   # OpenAI vectors have length 1, so dot = cosine similarity
            if score > best_score:
                best_key, best_score = key, score
        print(f"   [log] closest saved question: '{best_key}' (similarity {best_score:.2f})")
        return best_key, best_score

💡 How "same meaning" is measured

Compare the new question's vector with every saved one. The dot product gives a score: about 1.0 for the same meaning, about 0 for unrelated. Typical scores you'll see:

New questionClosest savedScoreResult (threshold 0.70)
Who is Elon Musk?elon musk≈ 0.84✅ reuse
Tell me about Marie Curiemarie curie≈ 0.78✅ reuse
Albert Einsteinmarie curie≈ 0.41❌ ask OpenAI

Einstein and Curie score higher than Curie and Musk because both are physicists, but nowhere near "same question".

2c · call_openai_model: the paid step

obs_demo_langsmith.py · lines 106–118
    @traceable(name="call_openai_model", run_type="chain")
    def call_openai_model(self, question: str):
        response = client.chat.completions.create(
            model=CHAT_MODEL,
            reasoning_effort="none",   # answer straight away, no hidden "thinking" tokens
            messages=[
                {"role": "system", "content": "Give exactly 2 short lines about this person's personality and achievements."},
                {"role": "user", "content": f"Tell me about {question}"},
            ],
        )
        usage = response.usage
        cost = usage.prompt_tokens / 1e6 * PRICE_INPUT + usage.completion_tokens / 1e6 * PRICE_OUTPUT
        return response.choices[0].message.content.strip(), usage.total_tokens, cost
  • Two messages: a system message with the rule ("exactly 2 short lines") and the user's question.
  • reasoning_effort="none": gpt-6-luna can "think" before answering, which costs extra hidden tokens. For a two-line answer we switch that off.
  • Cost: input tokens × input price + output tokens × output price. For 27 tokens in and 40 out: 27 × $0.10/1M + 40 × $0.50/1M ≈ $0.000023.

It only prints, but because of @traceable every call becomes a named step in the trace, with its details attached. Later you can count them in LangSmith: "how many semantic hits today?"

⚠️ The run_type labels

run_type tells LangSmith what kind of step this is (embedding, tool, chain, llm), so it can show the right icon and let you filter by type. It doesn't change what the code does.

The graph: three nodes and two routers

obs_demo_langsmith.py · lines 129–175
def build_graph(agent: PersonalityAgent):

    def check_exact_cache(state: AgentState) -> dict:
        key = clean(state["query"])
        if key in agent.cache:
            agent.record_event("cache_hit_exact", {"question": key})
            return {"response": agent.cache[key], "cache_hit_type": "exact", "cost": 0.0, "tokens": 0}
        return {"cache_hit_type": "miss"}

    def check_semantic_cache(state: AgentState) -> dict:
        best_key, score = agent.find_semantic_match(state["query"])
        if best_key and score >= SIMILARITY_THRESHOLD:
            agent.record_event("cache_hit_semantic",
                               {"question": state["query"], "matched": best_key, "similarity": round(score, 2)})
            # Only a tiny embedding cost was spent (printed above), no LLM cost
            return {"response": agent.cache[best_key], "cache_hit_type": "semantic",
                    "similarity": score, "cost": 0.0, "tokens": 0}
        return {"cache_hit_type": "miss", "similarity": score}

    def call_llm(state: AgentState) -> dict:
        question = state["query"]
        agent.record_event("llm_call_started", {"question": question})
        start = time.perf_counter()
        answer, tokens, cost = agent.call_openai_model(question)
        seconds = time.perf_counter() - start

        key = clean(question)                       # save for next time, in BOTH caches
        agent.cache[key] = answer
        agent.embeddings[key] = agent.get_embedding(key)
        agent.record_event("answer_cached", {"question": key, "llm_seconds": round(seconds, 2)})
        return {"response": answer, "cache_hit_type": "fresh", "cost": cost, "tokens": tokens}

    def after_exact(state: AgentState) -> str:
        return END if state["cache_hit_type"] == "exact" else "check_semantic_cache"

    def after_semantic(state: AgentState) -> str:
        return END if state["cache_hit_type"] == "semantic" else "call_llm"

    graph = StateGraph(AgentState)
    graph.add_node("check_exact_cache", check_exact_cache)
    graph.add_node("check_semantic_cache", check_semantic_cache)
    graph.add_node("call_llm", call_llm)
    graph.set_entry_point("check_exact_cache")
    graph.add_conditional_edges("check_exact_cache", after_exact)
    graph.add_conditional_edges("check_semantic_cache", after_semantic)
    graph.add_edge("call_llm", END)
    return graph.compile()

💡 Read it in this order

  1. check_exact_cache: cleaned question in the cache? Return the saved answer, with cost 0. Otherwise mark it "miss".
  2. check_semantic_cache: find the closest saved question. Score at or above 0.70? Reuse its answer. Otherwise "miss".
  3. call_llm: ask OpenAI, time it, then save the answer and its embedding so future questions can match it.
  4. after_exact / after_semantic: the routers. They read cache_hit_type and return the name of the next node, or END.
  5. The wiring at the bottom: start at check_exact_cache, use the routers after the first two nodes, and always end after call_llm.

🍛 Analogy

Three counters at a passport office: "already processed?" → "a very similar case on file?" → "process it fresh". At each counter an officer (the router) decides: done, or next counter.

⚠️ One small inefficiency to spot

For a new question, find_semantic_match computes its embedding, and then call_llm computes the same embedding again to save it. You can see the two embedding lines in the output for Marie Curie. It costs almost nothing, but it's a nice exercise to fix (see Exercises).

One question = one trace

obs_demo_langsmith.py · lines 181–189
@traceable(name="personality_query", run_type="chain", metadata={"app": "personality_bot", "version": "2.0"})
def run_query(graph, query: str) -> dict:
    start = time.perf_counter()
    result = graph.invoke({"query": query})
    seconds = time.perf_counter() - start
    print(f"   [metric] {result['cache_hit_type'].upper()} | {seconds:.2f}s | "
          f"{result.get('tokens', 0)} tokens | ${result.get('cost', 0.0):.6f}")
    print(f"   -> {result['response']}")
    return result

This is the root of each trace. Everything that happens inside graph.invoke (nodes, embeddings, OpenAI calls, events) is nested under it. The metadata is attached to every trace, so in LangSmith you can filter "show me only version 2.0 of personality_bot". It also prints the summary metric line: hit type, seconds, tokens and cost.

The main block: seven questions, then session metrics

obs_demo_langsmith.py · lines 192–222
if __name__ == "__main__":
    agent = PersonalityAgent()
    graph = build_graph(agent)

    questions = [
        "Elon Musk",                   # fresh: asked for the first time
        "Elon Musk",                   # exact hit: same text
        "Who is Elon Musk?",           # semantic hit (if similarity >= threshold): same meaning
        "Marie Curie",                 # fresh
        "  marie curie ",              # exact hit after cleaning (lower case, extra spaces)
        "Tell me about Marie Curie",   # semantic hit (if similarity >= threshold)
        "Albert Einstein",             # fresh
    ]

    counts = {"exact": 0, "semantic": 0, "fresh": 0}
    total_cost, total_tokens = 0.0, 0
    for i, question in enumerate(questions, 1):
        print(f"\n[{i}/{len(questions)}] {question!r}")
        result = run_query(graph, question)
        counts[result["cache_hit_type"]] += 1
        total_cost += result.get("cost", 0.0)
        total_tokens += result.get("tokens", 0)

    print("\n=== SESSION METRICS ===")
    print(f"Questions        : {len(questions)}")
    print(f"Exact cache hits : {counts['exact']}")
    print(f"Semantic hits    : {counts['semantic']}")
    print(f"LLM calls        : {counts['fresh']}")
    print(f"Cache hit rate   : {100 * (counts['exact'] + counts['semantic']) / len(questions):.0f}%")
    print(f"LLM tokens       : {total_tokens}")
    print(f"LLM cost         : ${total_cost:.6f}")

The question list is designed to hit every path: fresh, exact, semantic, exact-after-cleaning. The loop adds up the counts, tokens and cost, and prints a session summary at the end: the kind of numbers you'd put on a dashboard.

🌍 What the session metrics tell a business

57% of questions were answered from the cache. At scale (say 1 lakh questions a day), that's 57,000 fewer model calls: lower cost and much faster answers for those users. This is exactly the kind of metric you put on a dashboard and watch over time.

⚠️ The risk of a semantic cache

Set the threshold too low and different questions get the same answer: "Marie Curie's daughter" might match "Marie Curie" and get the wrong person's story. That's why the [log] line prints the score. Watch these scores on real traffic before choosing a threshold.

Exercises for learners

1. Change the threshold to 0.90. Which questions change from SEMANTIC to FRESH, and how do the session metrics change?

Questions 3 and 6 (scores ≈ 0.84 and ≈ 0.78) become FRESH: 5 LLM calls instead of 3, hit rate drops from 57% to 29%, and cost goes up. Safer, but more expensive.

2. Remove the double embedding for new questions.

Have check_semantic_cache return the vector it computed (add a vector field to the State), and let call_llm save that vector instead of calling get_embedding again.

3. Add a new event, "slow_answer", when the LLM takes more than 2 seconds.

In call_llm, after measuring seconds: if seconds > 2: agent.record_event("slow_answer", {"question": question, "seconds": round(seconds, 2)}). Then filter for it in LangSmith.

4. Put a wrong API key in .env and run it. What does the trace show?

The ChatOpenAI step (and its parents) turns red with the authentication error, and nothing is cached. Compare with the original code, which would have cached the error text as the "answer".

5. Ask "Marie Curie's daughter". Does the semantic cache wrongly reuse the Marie Curie answer?

Look at the [log] line's score. If it's above the threshold, that's a false match: a good discussion of why semantic caches need careful tuning.

"""
Observability demo with LangSmith  -  by Shivank Agarwal
=========================================================

WHAT IT DOES
    A tiny "personality bot": you give it a famous person's name and it answers in 2 lines.
    Two caches make repeated questions free, and LangSmith records every step, so for
    each question you can open a TRACE and see exactly what happened, how long it took
    and what it cost.

        question
           |
           v
    [check_exact_cache] ----- hit ----> END   (same question asked before: free, instant)
           | miss
           v
    [check_semantic_cache] -- hit ----> END   (a question with the same MEANING: almost free)
           | miss
           v
    [call_llm] -----------------------> END   (ask OpenAI, then save the answer in both caches)

THE 4 MELT PILLARS, AND WHERE THEY ARE IN THIS FILE
    Metrics -> tokens, cost and time for every question, plus session totals at the end
    Events  -> record_event("cache_hit_exact", ...) etc. appear as steps in the trace
    Logs    -> wrap_openai() stores every prompt and every answer inside the trace
    Traces  -> @traceable + LangGraph: one tree per question in LangSmith

HOW TO RUN
    1.  pip install -r requirements.txt
    2.  Create a free LangSmith account at https://smith.langchain.com -> Settings -> API Keys
    3.  Copy .env.example to .env and fill in your two keys
    4.  python obs_demo_langsmith.py
    5.  Open https://smith.langchain.com -> Tracing Projects -> observability_demo
"""
import time
from typing import TypedDict

import numpy as np
from dotenv import load_dotenv
from langgraph.graph import StateGraph, END
from langsmith import traceable
from langsmith.wrappers import wrap_openai
from openai import OpenAI

load_dotenv()   # reads OPENAI_API_KEY and the LANGSMITH_* settings from .env

CHAT_MODEL = "gpt-6-luna"                    # OpenAI's small, fast, cheap model
EMBEDDING_MODEL = "text-embedding-3-small"   # turns text into a list of numbers (a vector)

# Prices in US$ per 1 million tokens (check OpenAI's pricing page, they change)
PRICE_INPUT, PRICE_OUTPUT, PRICE_EMBEDDING = 0.10, 0.50, 0.02

SIMILARITY_THRESHOLD = 0.70   # how close (0 to 1) a new question must be to reuse an old answer

# wrap_openai: one line, and every OpenAI call (prompt, answer, model, tokens, time)
# is logged to LangSmith automatically.
client = wrap_openai(OpenAI())


# ---------------------------------------------------------------------------
# The State: what the graph knows about ONE question
# ---------------------------------------------------------------------------
class AgentState(TypedDict, total=False):
    query: str            # the question, e.g. "Elon Musk"
    response: str         # the answer
    cache_hit_type: str   # "exact", "semantic", "fresh" (or "miss" while still looking)
    similarity: float     # best similarity score found in the semantic cache
    cost: float           # US$ spent on the LLM for this question
    tokens: int           # LLM tokens used for this question


def clean(text: str) -> str:
    """'  Marie Curie ' and 'marie curie' should count as the same question."""
    return " ".join(text.lower().split())


# ---------------------------------------------------------------------------
# The Agent: caches + the OpenAI calls, each one traced
# ---------------------------------------------------------------------------
class PersonalityAgent:
    def __init__(self):
        self.cache = {}        # cleaned question -> answer
        self.embeddings = {}   # cleaned question -> its embedding vector

    @traceable(name="get_embedding", run_type="embedding")
    def get_embedding(self, text: str) -> np.ndarray:
        response = client.embeddings.create(model=EMBEDDING_MODEL, input=text)
        tokens = response.usage.total_tokens
        print(f"   [metric] embedding: {tokens} tokens, ${tokens / 1e6 * PRICE_EMBEDDING:.7f}")
        return np.array(response.data[0].embedding)

    @traceable(name="find_semantic_match", run_type="tool")
    def find_semantic_match(self, query: str):
        """Return (closest saved question, similarity score)."""
        if not self.embeddings:
            return None, 0.0
        query_vector = self.get_embedding(clean(query))
        best_key, best_score = None, -1.0          # start below any real score
        for key, vector in self.embeddings.items():
            score = float(np.dot(query_vector, vector))   # OpenAI vectors have length 1, so dot = cosine similarity
            if score > best_score:
                best_key, best_score = key, score
        print(f"   [log] closest saved question: '{best_key}' (similarity {best_score:.2f})")
        return best_key, best_score

    @traceable(name="call_openai_model", run_type="chain")
    def call_openai_model(self, question: str):
        response = client.chat.completions.create(
            model=CHAT_MODEL,
            reasoning_effort="none",   # answer straight away, no hidden "thinking" tokens
            messages=[
                {"role": "system", "content": "Give exactly 2 short lines about this person's personality and achievements."},
                {"role": "user", "content": f"Tell me about {question}"},
            ],
        )
        usage = response.usage
        cost = usage.prompt_tokens / 1e6 * PRICE_INPUT + usage.completion_tokens / 1e6 * PRICE_OUTPUT
        return response.choices[0].message.content.strip(), usage.total_tokens, cost

    @traceable(name="record_event", run_type="tool")
    def record_event(self, event_name: str, details: dict):
        """An EVENT: a meaningful moment we want to find and count later."""
        print(f"   [event] {event_name} {details}")


# ---------------------------------------------------------------------------
# The graph: 3 nodes + 2 routers  (LangGraph traces every node automatically)
# ---------------------------------------------------------------------------
def build_graph(agent: PersonalityAgent):

    def check_exact_cache(state: AgentState) -> dict:
        key = clean(state["query"])
        if key in agent.cache:
            agent.record_event("cache_hit_exact", {"question": key})
            return {"response": agent.cache[key], "cache_hit_type": "exact", "cost": 0.0, "tokens": 0}
        return {"cache_hit_type": "miss"}

    def check_semantic_cache(state: AgentState) -> dict:
        best_key, score = agent.find_semantic_match(state["query"])
        if best_key and score >= SIMILARITY_THRESHOLD:
            agent.record_event("cache_hit_semantic",
                               {"question": state["query"], "matched": best_key, "similarity": round(score, 2)})
            # Only a tiny embedding cost was spent (printed above), no LLM cost
            return {"response": agent.cache[best_key], "cache_hit_type": "semantic",
                    "similarity": score, "cost": 0.0, "tokens": 0}
        return {"cache_hit_type": "miss", "similarity": score}

    def call_llm(state: AgentState) -> dict:
        question = state["query"]
        agent.record_event("llm_call_started", {"question": question})
        start = time.perf_counter()
        answer, tokens, cost = agent.call_openai_model(question)
        seconds = time.perf_counter() - start

        key = clean(question)                       # save for next time, in BOTH caches
        agent.cache[key] = answer
        agent.embeddings[key] = agent.get_embedding(key)
        agent.record_event("answer_cached", {"question": key, "llm_seconds": round(seconds, 2)})
        return {"response": answer, "cache_hit_type": "fresh", "cost": cost, "tokens": tokens}

    def after_exact(state: AgentState) -> str:
        return END if state["cache_hit_type"] == "exact" else "check_semantic_cache"

    def after_semantic(state: AgentState) -> str:
        return END if state["cache_hit_type"] == "semantic" else "call_llm"

    graph = StateGraph(AgentState)
    graph.add_node("check_exact_cache", check_exact_cache)
    graph.add_node("check_semantic_cache", check_semantic_cache)
    graph.add_node("call_llm", call_llm)
    graph.set_entry_point("check_exact_cache")
    graph.add_conditional_edges("check_exact_cache", after_exact)
    graph.add_conditional_edges("check_semantic_cache", after_semantic)
    graph.add_edge("call_llm", END)
    return graph.compile()


# ---------------------------------------------------------------------------
# One question = one trace in LangSmith
# ---------------------------------------------------------------------------
@traceable(name="personality_query", run_type="chain", metadata={"app": "personality_bot", "version": "2.0"})
def run_query(graph, query: str) -> dict:
    start = time.perf_counter()
    result = graph.invoke({"query": query})
    seconds = time.perf_counter() - start
    print(f"   [metric] {result['cache_hit_type'].upper()} | {seconds:.2f}s | "
          f"{result.get('tokens', 0)} tokens | ${result.get('cost', 0.0):.6f}")
    print(f"   -> {result['response']}")
    return result


if __name__ == "__main__":
    agent = PersonalityAgent()
    graph = build_graph(agent)

    questions = [
        "Elon Musk",                   # fresh: asked for the first time
        "Elon Musk",                   # exact hit: same text
        "Who is Elon Musk?",           # semantic hit (if similarity >= threshold): same meaning
        "Marie Curie",                 # fresh
        "  marie curie ",              # exact hit after cleaning (lower case, extra spaces)
        "Tell me about Marie Curie",   # semantic hit (if similarity >= threshold)
        "Albert Einstein",             # fresh
    ]

    counts = {"exact": 0, "semantic": 0, "fresh": 0}
    total_cost, total_tokens = 0.0, 0
    for i, question in enumerate(questions, 1):
        print(f"\n[{i}/{len(questions)}] {question!r}")
        result = run_query(graph, question)
        counts[result["cache_hit_type"]] += 1
        total_cost += result.get("cost", 0.0)
        total_tokens += result.get("tokens", 0)

    print("\n=== SESSION METRICS ===")
    print(f"Questions        : {len(questions)}")
    print(f"Exact cache hits : {counts['exact']}")
    print(f"Semantic hits    : {counts['semantic']}")
    print(f"LLM calls        : {counts['fresh']}")
    print(f"Cache hit rate   : {100 * (counts['exact'] + counts['semantic']) / len(questions):.0f}%")
    print(f"LLM tokens       : {total_tokens}")
    print(f"LLM cost         : ${total_cost:.6f}")
