The inventory agent: from one prompt to a production-style AI assistant

A shop manager asks "Should I reorder toothpaste?" and gets an answer based on live stock data. The app is built in eight small versions; each one adds exactly one idea: a UI, a database and tools, guardrails, a cache, an email action, tracing and a calculation tool. Read them in order and you've seen how a real AI platform is put together.

1

What it does, in one minute

💡 The story

A small shop sells 19 products. For each one we know the current stock, the average daily demand and the lead time (how many days a new delivery takes). The question is always the same: will I run out before new stock can arrive?

days remaining = current stock ÷ daily demand
if days remaining ≤ lead time  →  reorder at least (daily demand × lead time) units

toothpaste: 20 in stock, 5 sold per day, 4-day delivery
            20 ÷ 5 = 4 days left, which is ≤ 4  →  reorder 5 × 4 = 20 units now

The final version (v7) answers this in a chat window, for any product, using the real database. It also blocks attacks, reuses recent answers, can email an alert and records a trace of every question.

🍛 Analogy: a kirana store assistant who grows into a manager

Day 1, the new assistant can only answer if you read the numbers out to them (v0). Then they get a notepad (v1), then access to the stock register (v2), then they learn to ignore pranksters (v3), remember answers they gave this morning (v4), send a message to the supplier when you say so (v5), keep a diary of every decision (v6), and finally use a calculator instead of mental maths (v7).

How to run it

⌨️ Setup (5 minutes)

  1. Keep all files in one folder: the eight inventoryplanner_v*.py files, database.py, requirements.txt, .env.example, README.md.
  2. Install: pip install -r requirements.txt (Python 3.10+).
  3. Copy .env.example to .env. Every version needs OPENAI_API_KEY. The email button (v5–v7) needs the EMAIL_* settings; for Gmail use an App Password, not your normal password. Tracing (v6–v7) needs the LANGSMITH_* settings.
  4. Run any version: python inventoryplanner_v0.py prints to the terminal; v1–v7 print a link (http://127.0.0.1:7860) to open in the browser.
  5. The database file inventory.db is created automatically the first time v2 or later runs.

💡 What you see in the browser (v7)

A chat window with five example questions underneath, a line of cache statistics with "Refresh" and "Clear cache" buttons, and a small "Send an inventory alert" form (subject, body, Send email). The terminal shows a [tool call] line every time the agent uses a tool.

v0

One prompt, one answer

inventoryplanner_v0.py · lines 10–40
from dotenv import load_dotenv
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

load_dotenv()   # reads OPENAI_API_KEY from the .env file

# The model: gpt-6-luna with reasoning off = fast, cheap, answers straight away
llm = ChatOpenAI(model="gpt-6-luna", reasoning_effort="none")

# A prompt with {blanks} that we fill in below
prompt = ChatPromptTemplate.from_messages([
    ("system", "You are an inventory management expert. Analyze inventory situations "
               "and give clear reorder recommendations."),
    ("human", """Should I reorder {product}? If so, how much?

Current stock: {current_stock} units
Average demand: {average_demand} units per day
Lead time: {lead_time} days

Give your recommendation and reasoning."""),
])

chain = prompt | llm    # "pipe": fill the prompt, then send it to the model

response = chain.invoke({
    "product": "toothpaste",
    "current_stock": 20,
    "average_demand": 5,
    "lead_time": 4,
})
print(response.content)

💡 In plain words

  • llm: the model. reasoning_effort="none" means "answer straight away, don't think at length": faster and cheaper for simple questions.
  • prompt: a template with {blanks}. The system message gives the model its role; the human message is the question.
  • prompt | llm: the pipe means "fill in the prompt, then send it to the model".
  • invoke: fills the blanks with toothpaste's numbers and runs it.
Example output (what you would see; exact text and numbers vary)
Yes, reorder toothpaste now.

Reasoning:
- At 5 units a day, your 20 units will last about 4 days.
- A new delivery takes 4 days to arrive, so you would run out just as it lands, with no safety margin.

Recommendation: order at least 20 units today (5 units/day x 4 days of lead time). If daily sales vary,
add a small safety buffer of 5-10 units and order 25-30 in total.

⚠️ The limitation

Someone has to know and type the numbers. And the model does the arithmetic in its head, which it usually gets right but can get wrong. Versions 2 and 7 fix these two problems.

def init_database(db_path: str = DB_PATH) -> bool:
    """Create the table (if missing) and add the sample products (if missing)."""
    try:
        conn = sqlite3.connect(db_path)
        conn.execute("""
            CREATE TABLE IF NOT EXISTS inventory (
                id INTEGER PRIMARY KEY,
                product_name TEXT UNIQUE NOT NULL,
                current_stock INTEGER NOT NULL,
                average_demand REAL NOT NULL,
                lead_time INTEGER NOT NULL,
                last_updated TIMESTAMP DEFAULT CURRENT_TIMESTAMP
            )
        """)
        conn.executemany("""
            INSERT OR IGNORE INTO inventory (product_name, current_stock, average_demand, lead_time)
            VALUES (?, ?, ?, ?)
        """, SAMPLE_DATA)
        conn.commit()      # save the changes to the file
        conn.close()
        return True
    except sqlite3.Error as e:
        print(f"Error initializing database: {e}")
        return False


def get_db_connection(db_path: str = DB_PATH) -> sqlite3.Connection:
    """Open a connection to the database."""
    return sqlite3.connect(db_path)

💡 In plain words

  • SQLite is a database stored in a single file (inventory.db). No server to install.
  • CREATE TABLE IF NOT EXISTS creates the table only the first time. INSERT OR IGNORE adds the 19 sample products only if they aren't there yet, so running it twice is safe.
  • commit() saves the changes to the file; close() releases it.

The tools: Python functions the model may call

@tool
def get_inventory_data(product_name: str) -> str:
    """Get stock, average daily demand and lead time for ONE product from the database."""
    conn = get_db_connection()
    row = conn.execute(
        "SELECT product_name, current_stock, average_demand, lead_time "
        "FROM inventory WHERE product_name LIKE ?", (f"%{product_name}%",)
    ).fetchone()
    conn.close()
    if not row:
        return f"Product '{product_name}' not found in inventory database"
    return (f"Product: {row[0]}, Current Stock: {row[1]} units, "
            f"Average Demand: {row[2]} units/day, Lead Time: {row[3]} days")
inventoryplanner_v2.py · lines 49–65
@tool
def get_all_inventory() -> str:
    """Get the status of ALL products, marking the ones that are running low."""
    conn = get_db_connection()
    rows = conn.execute(
        "SELECT product_name, current_stock, average_demand, lead_time "
        "FROM inventory ORDER BY product_name"
    ).fetchall()
    conn.close()
    if not rows:
        return "No inventory data found"
    lines = []
    for name, stock, demand, lead_time in rows:
        days_remaining = stock / demand if demand > 0 else 0
        status = "LOW STOCK" if days_remaining <= lead_time else "OK"
        lines.append(f"{name}: {stock} units, {days_remaining:.1f} days remaining ({status})")
    return "Current inventory status:\n" + "\n".join(lines)

💡 What makes a function a "tool"

  • @tool turns the function into something the model can request. The model sees its name, its arguments and its docstring, and uses the docstring to decide when to call it. Write docstrings for the model, not just for humans.
  • The ? in the SQL is a parameter. The product name is passed separately, so a user can't sneak SQL commands in (no SQL injection).
  • LIKE '%sham%' matches any product name that contains the text, and SQLite's LIKE ignores upper and lower case, so "Shampoo" and "sham" both find shampoo.

# The agent: the model + the tools + the instructions

SYSTEM_PROMPT = """You are an inventory management expert with access to a real-time inventory database.

When a user asks about an inventory decision:
1. First get the current data for the product with get_inventory_data
2. Decide if reordering is needed
3. Give a clear recommendation with reasoning

Key rules:
- Days remaining = current_stock / average_demand
- If days remaining <= lead time, recommend reordering
- Recommend ordering at least average_demand x lead_time units
- For general questions, use get_all_inventory to show the overall status

Always base your answer on the database data, not on assumptions. Be clear and concise."""

tools = [get_inventory_data, get_all_inventory]
agent = create_agent(model=llm, tools=tools, system_prompt=SYSTEM_PROMPT)


def run_agent(question: str) -> str:
    """Ask the agent one question. Prints each tool call so you can follow along in the terminal."""
    result = agent.invoke({"messages": [{"role": "user", "content": question}]})
    for message in result["messages"]:
        for call in getattr(message, "tool_calls", None) or []:
            print(f"[tool call] {call['name']}({call['args']})")
    return result["messages"][-1].text     # the agent's final answer, as plain text

💡 How the agent works

  1. create_agent bundles the model, the tools and the system prompt.
  2. On invoke, the model reads the question and decides: answer now, or call a tool first?
  3. If it asks for a tool, LangChain runs the Python function and gives the result back to the model.
  4. This repeats until the model writes a final answer. result["messages"] holds the whole conversation, including every tool call; the last message is the answer.
Example output (what you would see; exact text and numbers vary)
(terminal)

(chat window)

Assistant: Yes, reorder toothpaste now. You have 20 units and sell about 5 a day, so that's
           4 days of stock, exactly the 4-day delivery time. Order at least 20 units today

🍛 Analogy: RAG

An open-book exam. Instead of answering from memory, the student looks up the right page first (retrieval), then writes the answer (generation). That's Retrieval-Augmented Generation: the answer is based on your data, today's numbers, not whatever the model remembers.

Guardrails: check every message before the AI sees it

inventoryplanner_v3.py · lines 32–63
class Guardrails:
    BLOCKED_PATTERNS = {
        "prompt injection": [
            "ignore previous instructions", "ignore all previous instructions",
            "forget everything above", "forget the previous instructions", "new instructions:",
            "override instructions", "ignore system prompt", "system:", "assistant:", "human:",
        ],
        "role switching": [
            "you are now", "act as", "pretend to be", "roleplay as", "assume the role", "switch to",
        ],
        "system prompt extraction": [
            "what are your instructions", "show me your prompt", "repeat your instructions",
            "what is your system prompt", "display your guidelines", "reveal your instructions",
        ],
        "code injection": ["<!-->", "<script>", "javascript:", "eval(", "exec("],
        "jailbreak": ["dan mode", "developer mode", "jailbreak", "unrestricted mode"],
    }
    MAX_LENGTH = 5000

    def check(self, user_input: str) -> tuple[bool, str]:
        """Return (is_safe, reason). reason explains why a message was blocked."""
        if len(user_input) > self.MAX_LENGTH:
            return False, "Input too long"
        # Very long message made of very few different characters (e.g. "aaaa...") = spam / DoS attempt
        if len(user_input) > 100 and len(set(user_input)) < len(user_input) / 20:
            return False, "Suspicious input pattern detected"
        text = user_input.lower()
        for category, patterns in self.BLOCKED_PATTERNS.items():
            for pattern in patterns:
                if pattern in text:
                    return False, f"Blocked: possible {category} ('{pattern}')"
        return True, ""

💡 In plain words

check() runs three tests in order: is the message too long, is it a long run of the same few characters (spam), and does it contain any blocked phrase? The first failed test returns False plus a reason. In inventory_chat the check runs first, so a blocked message never reaches the model: no cost, no risk. The system prompt also gained "security rules" (defence in depth).

A cache: reuse recent answers

inventoryplanner_v4.py · lines 73–110
class InputCache:
    def __init__(self, max_size: int = 500, ttl_seconds: int = 300):
        self.cache = {}                 # question hash -> (answer, time saved)
        self.max_size = max_size        # keep at most this many answers
        self.ttl_seconds = ttl_seconds  # an answer expires after this many seconds
        self.hits = 0
        self.misses = 0

    def _key(self, text: str) -> str:
        """'Should I reorder toothpaste?' and 'should i reorder toothpaste? ' get the same key."""
        return hashlib.md5(text.lower().strip().encode()).hexdigest()

    def get(self, text: str):
        key = self._key(text)
        if key in self.cache:
            answer, saved_at = self.cache[key]
            if time.time() - saved_at <= self.ttl_seconds:
                self.hits += 1
                return answer
            del self.cache[key]         # too old: throw it away
        self.misses += 1
        return None

    def set(self, text: str, answer: str):
        self.cache[self._key(text)] = (answer, time.time())
        if len(self.cache) > self.max_size:              # full: remove the oldest answer
            oldest_key = min(self.cache, key=lambda k: self.cache[k][1])
            del self.cache[oldest_key]

    def clear(self):
        self.cache.clear()
        self.hits = self.misses = 0

    def stats(self) -> dict:
        total = self.hits + self.misses
        hit_rate = 100 * self.hits / total if total else 0
        return {"size": len(self.cache), "max_size": self.max_size, "hits": self.hits,
                "misses": self.misses, "hit_rate": f"{hit_rate:.1f}%", "ttl_seconds": self.ttl_seconds}

def inventory_chat(message: str) -> str:

💡 In plain words

  • Key: the question in lower case with spaces trimmed, turned into a short fingerprint with MD5. "Should I reorder toothpaste?" and " should i reorder TOOTHPASTE? " get the same key.
  • get: found and younger than 5 minutes (TTL) → a hit. Too old → delete it and count a miss.
  • set: save the answer with the current time. If more than 500 answers are stored, remove the oldest.
  • Order in inventory_chat: guardrail → cache → agent → save. Cached answers start with 🔄 so you can see them.

Stock changes. If a delivery arrives two minutes after an answer was cached, the next person asking gets the old answer for up to three more minutes. Keep the expiry short for live data, and clear the cache whenever the database is updated. Also: an exact-text cache only helps when people ask the same words; the Observability demo shows a semantic cache that matches meaning.

# ------------------------------------------------------------------
# Guardrails: a rule-based INPUT guardrail (checks the message BEFORE the AI sees it)
# ------------------------------------------------------------------
class Guardrails:
    BLOCKED_PATTERNS = {
        "prompt injection": [
            "ignore previous instructions", "ignore all previous instructions",
            "forget everything above", "forget the previous instructions", "new instructions:",
            "override instructions", "ignore system prompt", "system:", "assistant:", "human:",
        ],
        "role switching": [
            "you are now", "act as", "pretend to be", "roleplay as", "assume the role", "switch to",
        ],
        "system prompt extraction": [
            "what are your instructions", "show me your prompt", "repeat your instructions",
            "what is your system prompt", "display your guidelines", "reveal your instructions",
        ],
        "code injection": ["<!-->", "<script>", "javascript:", "eval(", "exec("],
        "jailbreak": ["dan mode", "developer mode", "jailbreak", "unrestricted mode"],
    }
    MAX_LENGTH = 5000

    def check(self, user_input: str) -> tuple[bool, str]:
        """Return (is_safe, reason). reason explains why a message was blocked."""
        if len(user_input) > self.MAX_LENGTH:
            return False, "Input too long"
        # Very long message made of very few different characters (e.g. "aaaa...") = spam / DoS attempt
        if len(user_input) > 100 and len(set(user_input)) < len(user_input) / 20:
            return False, "Suspicious input pattern detected"
        text = user_input.lower()
        for category, patterns in self.BLOCKED_PATTERNS.items():
            for pattern in patterns:
                if pattern in text:
                    return False, f"Blocked: possible {category} ('{pattern}')"
        return True, ""


guardrails = Guardrails()

# ------------------------------------------------------------------
# Cache: remember answers to repeated questions for 5 minutes
# ------------------------------------------------------------------
class InputCache:
    def __init__(self, max_size: int = 500, ttl_seconds: int = 300):
        self.cache = {}                 # question hash -> (answer, time saved)
        self.max_size = max_size        # keep at most this many answers
        self.ttl_seconds = ttl_seconds  # an answer expires after this many seconds
        self.hits = 0
        self.misses = 0

    def _key(self, text: str) -> str:
        """'Should I reorder toothpaste?' and 'should i reorder toothpaste? ' get the same key."""
        return hashlib.md5(text.lower().strip().encode()).hexdigest()

    def get(self, text: str):
        key = self._key(text)
        if key in self.cache:
            answer, saved_at = self.cache[key]
            if time.time() - saved_at <= self.ttl_seconds:
                self.hits += 1
                return answer
            del self.cache[key]         # too old: throw it away
        self.misses += 1
        return None

    def set(self, text: str, answer: str):
        self.cache[self._key(text)] = (answer, time.time())
        if len(self.cache) > self.max_size:              # full: remove the oldest answer
            oldest_key = min(self.cache, key=lambda k: self.cache[k][1])
            del self.cache[oldest_key]

    def clear(self):
        self.cache.clear()
        self.hits = self.misses = 0

    def stats(self) -> dict:
        total = self.hits + self.misses
        hit_rate = 100 * self.hits / total if total else 0
        return {"size": len(self.cache), "max_size": self.max_size, "hits": self.hits,
                "misses": self.misses, "hit_rate": f"{hit_rate:.1f}%", "ttl_seconds": self.ttl_seconds}

"""
database.py  -  the inventory database  (by Shivank Agarwal)

Creates a small SQLite database (a single file, inventory.db) with one table:

    product_name | current_stock | average_demand (units/day) | lead_time (days)

Versions v2 to v7 call init_database() at start-up, so the file is created
automatically the first time you run them.
"""
import sqlite3

DB_PATH = "inventory.db"

SAMPLE_DATA = [
    # (product, current stock, average daily demand, lead time in days)
    ("toothpaste", 20, 5.0, 4),
    ("shampoo", 15, 3.0, 5),
    ("soap", 50, 8.0, 3),
    ("detergent", 25, 4.5, 6),
    ("toilet_paper", 100, 12.0, 7),
    ("toothbrush", 30, 2.0, 3),
    ("mouthwash", 10, 1.0, 4),
    ("floss", 20, 1.5, 5),
    ("razor", 15, 0.5, 3),
    ("shaving_cream", 25, 1.0, 4),
    ("shaving_gel", 10, 0.5, 3),
    ("shaving_foam", 15, 1.0, 4),
    ("milk", 10, 2.0, 3),
    ("bread", 20, 1.0, 4),
    ("eggs", 30, 0.5, 3),
    ("cheese", 15, 1.0, 4),
    ("butter", 10, 0.5, 3),
    ("yogurt", 15, 1.0, 4),
    ("juice", 20, 2.0, 3),
]


def init_database(db_path: str = DB_PATH) -> bool:
    """Create the table (if missing) and add the sample products (if missing)."""
    try:
        conn = sqlite3.connect(db_path)
        conn.execute("""
            CREATE TABLE IF NOT EXISTS inventory (
                id INTEGER PRIMARY KEY,
                product_name TEXT UNIQUE NOT NULL,
                current_stock INTEGER NOT NULL,
                average_demand REAL NOT NULL,
                lead_time INTEGER NOT NULL,
                last_updated TIMESTAMP DEFAULT CURRENT_TIMESTAMP
            )
        """)
        conn.executemany("""
            INSERT OR IGNORE INTO inventory (product_name, current_stock, average_demand, lead_time)
            VALUES (?, ?, ?, ?)
        """, SAMPLE_DATA)
        conn.commit()      # save the changes to the file
        conn.close()
        return True
    except sqlite3.Error as e:
        print(f"Error initializing database: {e}")
        return False


def get_db_connection(db_path: str = DB_PATH) -> sqlite3.Connection:
    """Open a connection to the database."""
    return sqlite3.connect(db_path)
