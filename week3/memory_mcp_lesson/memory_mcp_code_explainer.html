Memory and MCP in code: an agent that remembers its customers, a chat that manages its history, and tools served over MCP

Two Python files build a customer-service agent that uses semantic, episodic and procedural memory, then teach it to update and save what it learns. One notebook shows the four ways to keep a conversation's history under control. The other serves two real tools (time and weather) from an MCP server and lets the model use them.

How to run it

  1. Install the packages: pip install -r requirements.txt
  2. Copy .env.example to .env and put your key in it: OPENAI_API_KEY=sk-...
  3. Run the demos: python memory_demo_1.py and python memory_demo_2.py
  4. Open the notebooks in Jupyter or Google Colab and run the cells from top to bottom. If OPENAI_API_KEY isn't already set, the notebook asks for it once.

💡 What's in each

  • semantic_memory: facts true for every customer: return period, shipping time, opening hours, product categories.
  • episodic_memory: one entry per customer: name, preferred contact, preferences, and recent interactions.
  • order_store and user_orders: stand for the company's order database. The "procedure" below knows how to look things up in them.

Dictionaries keep the flow easy to see. In production, facts would sit in a vector database, customer history in a database, and orders behind an API.

3. Step 1, semantic memory: pick the relevant facts

memory_demo_1.py · lines 109–125
    def get_semantic_facts(self, state: AgentState) -> AgentState:
        """Retrieve general world knowledge from semantic memory"""
        print("🔍 Accessing SEMANTIC MEMORY...")
        
        # Extract relevant semantic facts based on query
        relevant_facts = {}
        user_query = state.get("user_query", "").lower()
        
        if "return" in user_query:
            relevant_facts["return_policy"] = self.semantic_memory["company_policies"]["return_period"]
        if "shipping" in user_query:
            relevant_facts["shipping_info"] = self.semantic_memory["company_policies"]["shipping_time"]
        if "electronics" in user_query:
            relevant_facts["category_info"] = self.semantic_memory["product_categories"]["electronics"]
            
        state["semantic_facts"] = relevant_facts
        return state

Simple keyword matching: if the question contains "return", add the return policy. Only relevant facts go to the model, which keeps the prompt short (see Known limits for why "refund" would be missed).

5. Step 3, procedural memory: follow the lookup steps

memory_demo_1.py · lines 137–159
    def procedural_lookup(self, state: AgentState) -> AgentState:
        """Execute procedural memory - follow steps to query data stores"""
        print("🔄 Executing PROCEDURAL MEMORY...")
        
        user_id = state.get("user_id", "user_123")
        order_id = state.get("order_id")
        
        # Procedural steps:
        # 1. Look up user's orders
        user_order_ids = self.user_orders.get(user_id, [])
        
        # 2. If specific order requested, get its details
        if order_id and order_id in user_order_ids:
            order_details = self.order_store.get(order_id, {})
            state["order_details"] = {order_id: order_details}
        # 3. Otherwise get all user orders
        else:
            all_orders = {}
            for oid in user_order_ids:
                all_orders[oid] = self.order_store.get(oid, {})
            state["order_details"] = all_orders
            
        return state

A fixed recipe: find the customer's order IDs; if they asked about one order they own, fetch just that one; otherwise fetch them all. The know-how lives in this code, which is what "procedural" means: how to do the task.

⚠️ Which memory is which, really?

The code puts everything about a customer under episodic_memory. By the lecture's definitions it's a mix:

  • recent_interactions ("Complained about delayed shipping last month") are episodic: specific past events.
  • name, preferred_contact and preferences are lasting facts about the customer, so they're really semantic memory (a user profile).

A good class question: "Which lines here are events, and which are facts?"

3. The new step: detect a preference change and save it

memory_demo_2.py · lines 118–170
    def detect_and_update_preference(self, state: AgentState) -> AgentState:
        """
        Use the LLM to detect preference change requests in the user query.
        If a preference change is found, update episodic memory immediately
        so the SAME turn already reflects the new preference.
        """
        print("🔄 Checking for PREFERENCE UPDATES...")
        self.turn += 1

        prompt = f"""
You are a preference-change detector. Analyse the user message below.
If the user is requesting a change to any of their preferences (e.g. detail level,
language, contact method, shipping speed, etc.), respond with ONLY a valid JSON object
mapping preference key → new value, like:
{{"detail_level": "brief"}}

If there is NO preference change, respond with ONLY an empty JSON object: {{}}

User message: "{state['user_query']}"
"""
        result = json_llm.invoke(prompt)
        try:
            updates: Dict[str, Any] = json.loads(result.text)
        except json.JSONDecodeError:
            updates = {}
        if not isinstance(updates, dict):
            updates = {}

        state["preference_update"] = updates

        if updates:
            user_id = state["user_id"]
            if user_id in self.episodic_memory:
                old_prefs = {k: self.episodic_memory[user_id]["preferences"][k]
                             for k in updates if k in self.episodic_memory[user_id]["preferences"]}
                self.episodic_memory[user_id]["preferences"].update(updates)
                # Append to audit trail
                audit = self.episodic_memory[user_id].setdefault("preference_history", {})
                if not audit:
                    audit[f"turn_{self.turn - 1}"] = old_prefs  # seed state before first change
                audit[f"turn_{self.turn}"] = dict(updates)
                # Refresh the user_context so generate_response uses new prefs
                state["user_context"] = self.episodic_memory[user_id]
                print(f"   ✏️  Preference updated for {user_id}: {old_prefs} → {updates}")
                print(f"   📋 New preferences: {self.episodic_memory[user_id]['preferences']}")
                # Persist updated memory to JSON file
                with open(EPISODIC_MEMORY_FILE, "w") as f:
                    json.dump(self.episodic_memory, f, indent=2)
                print(f"   💾 Episodic memory saved to {EPISODIC_MEMORY_FILE}")
        else:
            print("   — No preference change detected.")

        return state

💡 Read it in four parts

  1. Ask the model (the prompt and json_llm.invoke): "Is the user changing a preference? Reply with JSON like {"detail_level": "brief"}, or {} if not."
  2. Read the answer safely (the try / isinstance checks): if it isn't a JSON dictionary, treat it as "no change".
  3. Update memory (inside if updates:): change the preference, record old and new values in preference_history (an audit trail), and refresh user_context so this same reply already uses the new preference.
  4. Save (the with open(...) block): write the whole memory to episodic_memory.json.

⚠️ Saved, but not yet loaded

The first lines of __init__ overwrite the JSON file with the defaults every time the program starts. So the memory survives within one run and is written to disk, but the next run doesn't read it back. That's on purpose for a repeatable demo; Exercise 1 makes it true long-term memory.

⚠️ The cost of the hot path

Every turn now makes two model calls (detect, then reply) instead of one, even when nothing changed, as in turns 1 and 3. For a busy app you'd move detection to the background, after the reply (Memory lecture slide 6).

def get_current_time(timezone: str = "UTC") -> str:
    """Get the current time in a given IANA timezone (e.g. 'Asia/Tokyo', 'Asia/Kolkata')."""
    from zoneinfo import ZoneInfo
    from datetime import datetime
    try:
        tz = ZoneInfo(timezone)
        now = datetime.now(tz)
        return f"Current time in {timezone}: {now.strftime('%Y-%m-%d %H:%M:%S %Z')}"
    except Exception as e:
        return f"Unknown timezone '{timezone}': {e}"


@mcp.tool()
def get_weather(city: str) -> str:
    """Get current weather for a city using Open-Meteo (no API key required)."""
    try:
        geo_resp = requests.get(
            "https://geocoding-api.open-meteo.com/v1/search",
            params={"name": city, "count": 1, "language": "en", "format": "json"},
            timeout=10,
        )
        geo_resp.raise_for_status()
        geo_data = geo_resp.json()
        if not geo_data.get("results"):
            return f"City '{city}' not found."
        loc = geo_data["results"][0]
        lat, lon = loc["latitude"], loc["longitude"]
        resolved_name = loc.get("name", city)

        wx_resp = requests.get(
            "https://api.open-meteo.com/v1/forecast",
            params={
                "latitude": lat,
                "longitude": lon,
                "current": "temperature_2m,relative_humidity_2m,apparent_temperature,wind_speed_10m,weather_code",
                "wind_speed_unit": "kmh",
                "timezone": "auto",
            },
            timeout=10,

        cur = wx_resp.json()["current"]
        desc = WMO_CODES.get(cur["weather_code"], f"Weather code {cur['weather_code']}")

            f"Weather in {resolved_name}: {desc}, "
            f"{cur['temperature_2m']}\u00b0C (feels like {cur['apparent_temperature']}\u00b0C), "
            f"Humidity: {cur['relative_humidity_2m']}%, Wind: {cur['wind_speed_10m']} km/h"

💡 What to point out

  • @mcp.tool() turns a normal function into an MCP tool. Its docstring becomes the description the model reads; its type hints become the input schema (MCP lecture slides 10 and 13).
  • get_current_time uses Python's own time-zone data, no internet needed.
  • get_weather makes two real web calls: city name → latitude/longitude, then the current weather there. WMO_CODES turns the weather code (e.g. 2) into words ("Partly cloudy").
  • Both tools return an error message instead of crashing, so the model can tell the user what went wrong.

2. The host: discover, ask the model, run the tools, ask again

fastmcp_demo_v1.ipynb · cell 5
from fastmcp import Client


async def chat_with_tools(user_message: str) -> str:
    """Send a message to OpenAI, dispatching tool calls through the FastMCP server."""
    async with Client(mcp) as client:
        tools = await client.list_tools()
        functions = [
            {
                "type": "function",
                "function": {
                    "name": t.name,
                    "description": t.description or "",
                    "parameters": t.input_schema,
                },
            }
            for t in tools
        ]

        messages = [{"role": "user", "content": user_message}]

        response = openai_client.chat.completions.create(
            model=MODEL,
            messages=messages,
            tools=functions,
            tool_choice="auto",
            reasoning_effort="none",   # answer straight away, no hidden "thinking" tokens
        )
        message = response.choices[0].message

        if message.tool_calls:
            messages.append({
                "role": "assistant",
                "content": message.content,
                "tool_calls": [tc.model_dump() for tc in message.tool_calls],
            })

            for tool_call in message.tool_calls:
                tool_name = tool_call.function.name
                tool_args = json.loads(tool_call.function.arguments)

                result = await client.call_tool(tool_name, tool_args)
                text = result.content[0].text if result.content else ""

                print(f"  [Tool: {tool_name}({tool_args})] => {text}")
                messages.append({
                    "role": "tool",
                    "content": text,
                    "tool_call_id": tool_call.id,
                })

            final_response = openai_client.chat.completions.create(
                model=MODEL,
                messages=messages,
                reasoning_effort="none",
            )
            return final_response.choices[0].message.content

        return message.content


print("chat_with_tools defined.")

💡 Read it in this order

  1. Connect: Client(mcp) opens a client to the server. Passing the server object connects in memory; no separate program is needed.
  2. Discover: list_tools() sends tools/list; each tool's name, description and input_schema are copied into OpenAI's function format.
  3. First call: the question plus the tool list go to gpt-6-luna. It either answers or asks for tools.
  4. Run the tools: for each request, client.call_tool() sends tools/call to the server, and the result goes back into the conversation as a "role": "tool" message with the matching tool_call_id.
  5. Second call: the model sees the results and writes the final answer.

Known limits (good discussion points)

  1. Keyword lookup misses synonyms. "Can I get a refund?" contains no "return", so no policy is fetched. Real systems search by meaning with embeddings (Memory slides 16–17).
  2. A missing order in demo 1. user_789 owns ORD-006, which isn't in order_store, so the model would be shown an empty {} for it. Demo 2 skips unknown IDs (if oid in self.order_store).
  3. Unknown customers get an empty context and are called "Customer". The agent doesn't say it couldn't find them.
  4. Demo 2 resets its memory on every start (the file is saved, never loaded). See Exercise 1.
  5. The detector can invent keys. Ask "please use a formal tone" and the model may return {"tone": "formal"}, which is added to the preferences as a brand-new key. See Exercise 3.
  6. Contact method is stored in two places. preferred_contact sits outside preferences, but the detector only updates preferences. "Contact me by SMS" would most likely add a new key inside preferences and leave preferred_contact as "email".
  7. Hard-coded deletion indices (4–7) in the notebook only fit this exact conversation.
  8. Summaries pile up. Summarizing a second time must fold the old summary into the new one, or earlier facts are lost (Memory slide 10).
  9. One round of tools in the MCP notebook, and tool output goes to the model as plain text without an "untrusted data" label (MCP slide 16).

    A customer-service agent built as a LangGraph pipeline of four steps:

      2. episodic memory   -> what we know about THIS customer (name, preferences, past chats)

        workflow.add_edge("episodic_memory", "procedural_memory")
        workflow.add_edge("procedural_memory", "generate_response")

    def detect_and_update_preference(self, state: AgentState) -> AgentState:
        """

@mcp.tool()
def get_current_time(timezone: str = "UTC") -> str:
    """Get the current time in a given IANA timezone (e.g. 'Asia/Tokyo', 'Asia/Kolkata')."""
    from zoneinfo import ZoneInfo
    from datetime import datetime
    try:
        tz = ZoneInfo(timezone)
        now = datetime.now(tz)
        return f"Current time in {timezone}: {now.strftime('%Y-%m-%d %H:%M:%S %Z')}"
    except Exception as e:
        return f"Unknown timezone '{timezone}': {e}"


@mcp.tool()
def get_weather(city: str) -> str:
    """Get current weather for a city using Open-Meteo (no API key required)."""
    try:
        geo_resp = requests.get(
            "https://geocoding-api.open-meteo.com/v1/search",
            params={"name": city, "count": 1, "language": "en", "format": "json"},
            timeout=10,
        )
        geo_resp.raise_for_status()
        geo_data = geo_resp.json()
        if not geo_data.get("results"):
            return f"City '{city}' not found."
        loc = geo_data["results"][0]
        lat, lon = loc["latitude"], loc["longitude"]
        resolved_name = loc.get("name", city)

        wx_resp = requests.get(
            "https://api.open-meteo.com/v1/forecast",
            params={
                "latitude": lat,
                "longitude": lon,
                "current": "temperature_2m,relative_humidity_2m,apparent_temperature,wind_speed_10m,weather_code",
                "wind_speed_unit": "kmh",
                "timezone": "auto",
            },
            timeout=10,
        )
        wx_resp.raise_for_status()
        cur = wx_resp.json()["current"]
        desc = WMO_CODES.get(cur["weather_code"], f"Weather code {cur['weather_code']}")
        return (
            f"Weather in {resolved_name}: {desc}, "
            f"{cur['temperature_2m']}\u00b0C (feels like {cur['apparent_temperature']}\u00b0C), "
            f"Humidity: {cur['relative_humidity_2m']}%, Wind: {cur['wind_speed_10m']} km/h"
        )
    except Exception as e:
        return f"Could not get weather for {city}: {e}"

from fastmcp import Client


async def chat_with_tools(user_message: str) -> str:
    """Send a message to OpenAI, dispatching tool calls through the FastMCP server."""
    async with Client(mcp) as client:
        tools = await client.list_tools()
        functions = [
            {
                "type": "function",
                "function": {
                    "name": t.name,
                    "description": t.description or "",
                    "parameters": t.input_schema,
                },
            }
            for t in tools
        ]

        messages = [{"role": "user", "content": user_message}]

        response = openai_client.chat.completions.create(
            model=MODEL,
            messages=messages,
            tools=functions,
            tool_choice="auto",
            reasoning_effort="none",   # answer straight away, no hidden "thinking" tokens
        )
        message = response.choices[0].message

        if message.tool_calls:
            messages.append({
                "role": "assistant",
                "content": message.content,
                "tool_calls": [tc.model_dump() for tc in message.tool_calls],
            })

            for tool_call in message.tool_calls:
                tool_name = tool_call.function.name
                tool_args = json.loads(tool_call.function.arguments)

                result = await client.call_tool(tool_name, tool_args)
                text = result.content[0].text if result.content else ""

                print(f"  [Tool: {tool_name}({tool_args})] => {text}")
                messages.append({
                    "role": "tool",
                    "content": text,
                    "tool_call_id": tool_call.id,
                })

            final_response = openai_client.chat.completions.create(
                model=MODEL,
                messages=messages,
                reasoning_effort="none",
            )
            return final_response.choices[0].message.content

        return message.content
