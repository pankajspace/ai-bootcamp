Exercise 1.1 — Word embeddings notebook

File: 1_GIVE_FIRST_Starter_Code/1_word_embeddings.ipynb

Story: A computer cannot read the word king. It only works with numbers. An embedding is a list of numbers that stands for a word, and words with similar meanings get similar lists. Your job is to look at these numbers and use them.

Run the cells from top to bottom. Fill in these blanks:

Paris is to France as ? is to India.

TODO 4Write a cosine_similarity(a, b) function using numpy

Exercise 1.3 — Retrieve, then Rerank web app

File: 1_GIVE_FIRST_Starter_Code/3_reranking_app.py

Story: Fast search (Exercise 1.2) is good at finding roughly related text, but it can be fooled by sentences that just repeat the question's words. A reranker (a cross-encoder) reads the question and each document together and gives a sharper relevance score. Real systems do both: retrieve many quickly, then rerank the few that came back.

Step 1: Retrievebi-encoder, fast, top K
→
Step 2: Rerankcross-encoder, slow, precise
→
Final orderbest answer first
TODO 1Embed the documents and the query, score them with cosine similarity, sort, keep top k

This is the same idea as Exercise 1.2, written with scikit-learn's cosine_similarity, which scores all documents in one call.

Need a hint?
  • bi_encoder.encode(documents) -> matrix (one row per document)
  • bi_encoder.encode([query]) -> matrix with ONE row
  • cosine_similarity(query_matrix, doc_matrix)[0] -> one score per document
TODO 2Score every (query, document) pair with the cross-encoder and sort best first
Need a hint?
  • Build pairs like [(query, doc1), (query, doc2), ...]
  • cross_encoder.predict(pairs) -> one score per pair (higher = more relevant)

Run it: python 3_reranking_app.py, open the link, click 1) Retrieve Top K, then 2) Rerank.

You are done when
  • Both tables show all 8 documents with a score
  • The order in the "Reranked" table is different from the "Top-K" table
  • Write down: which sentence is #1 before reranking, and which is #1 after?

Think about it (answer in 1–2 lines each)

  1. In Exercise 1.1, when we search with the raw vector for king − man + woman, the top word is king itself. Why?
  2. Why do we compare embeddings with cosine similarity (the angle) and not just by subtracting the numbers?
  3. A cross-encoder gives better scores. So why don't we run it on all one million documents in a real system?
  4. Exercise 1.3 has a document saying COVID-19 causes memory loss and confusion. That is not a common COVID symptom. Did the reranker push it down? What does that tell you about what a reranker checks?
  5. If you set K = 2 in Exercise 1.3, can the reranker still find the best document? Why or why not?
