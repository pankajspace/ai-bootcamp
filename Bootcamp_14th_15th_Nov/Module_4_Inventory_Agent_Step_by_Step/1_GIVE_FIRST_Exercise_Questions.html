What you will build

A chat assistant for a store manager. Ask "Should I reorder SKU-002?" and it reads the database, does the exact maths with tools, uses inventory best practices from a small knowledge base (RAG), and replies in plain English, in a web chat window.

Inventory words in 2 minutes

Think of a quick-commerce dark store (the warehouse behind a 10-minute grocery app). It must never run out of fast-selling items, but it also cannot overstock because shelf space and cash are limited. These words describe that balance:

WordPlain meaningExample (SKU-005, Laptop 15-inch)
SKUStock Keeping Unit: the ID of one productSKU-005
Current stockUnits on the shelf right now50 laptops
Lead timeDays between placing an order and receiving it30 days
Average daily demandUnits sold per day on average3 per day
Demand std devHow much daily sales jump around the average (standard deviation)1 per day (some days 2, some days 4)
Service levelHow sure you want to be that you will not run out before the delivery arrives99%
Z-scoreThe service level turned into a number from the statistics table. Higher = more caution99% → 2.33 (95% → 1.65)
Safety stockExtra buffer for bad days: Z × demand_std_dev × √lead_time2.33 × 1 × √30 = 12.76
Desired stock (= reorder point)What you must have to survive until the delivery comes: avg_daily_demand × lead_time + safety_stock3 × 30 + 12.76 = 102.76
Reorder quantityHow many to order now: max(0, desired − current), rounded up102.76 − 50 → 53 laptops
One sentence to remember

Order enough to cover the days you wait for delivery, plus a buffer for bad days, minus what you already have.

Step 01 — SQLite basics

File: 1_GIVE_FIRST_Starter_Code/01_sqlite_basics.py

Store products and suppliers in two tables linked by sku_id, and read them back together.

TODO 1Write a JOIN query that returns sku_id, sku_name, stock, lead_time_days, supplier_name for every product
Need a hint?
  • SELECT p.sku_id, p.sku_name, p.stock, s.lead_time_days, s.supplier_name
  • FROM products p JOIN suppliers s ON s.sku_id = p.sku_id ORDER BY p.sku_id
  • cur.execute(sql).fetchall() returns all rows
TODO 2Fetch ONE product (joined with its supplier) by sku_id; return it as a dict, or None if not found
Need a hint?
  • Same JOIN as above + WHERE UPPER(p.sku_id) = UPPER(?) (so "sku-002" also works)
  • cur.execute(sql, (sku_id,)).fetchone() returns one row or None
  • dict(row) turns a Row into a normal dict
You are done when the table prints 3 rows with the supplier names, Lookup sku-002 prints a dict (lower-case input still works) and Lookup SKU-999 prints None.

Step 02 — Embeddings basics

File: 1_GIVE_FIRST_Starter_Code/02_embeddings_basics.py

Six short notes about inventory. For each question, find the 3 most relevant notes using embeddings and a dot product. No database, no LLM.

TODO 1Embed the query, score it against every passage, and return the top k
Need a hint?
  • qv = model.encode(query, normalize_embeddings=True)

Step 08 — The full agent app

File: 1_GIVE_FIRST_Starter_Code/08_full_agent_app.py

Everything together: 3-table database with 10 products, a 13-note knowledge base, three tools, the agent loop and a Gradio chat window.

TODO 1Write the compute_stock_metrics tool (exact maths for one SKU)
Need a hint?
  • Inputs: avg_daily_demand, demand_std_dev, lead_time_days, service_level_pct, current_stock (all float)
  • z = Z_TABLE.get(round(service_level_pct), 1.65)
  • safety_stock = Z * demand_std_dev * sqrt(lead_time_days); desired_stock = avg_daily_demand * lead_time_days + safety_stock
  • reorder_quantity = max(0, math.ceil(desired_stock - current_stock)) (whole units)
  • Return a dict with z_score, safety_stock, desired_stock, reorder_quantity, reorder_needed
TODO 2One turn of the agent loop (same as Step 06)
Need a hint?
  • response = llm.invoke(messages); messages.append(response)
  • No tool_calls -> return response.text (the final answer as plain text)
  • Otherwise run each tool and append ToolMessage(content=json.dumps(result, default=str), tool_call_id=tc["id"])
You are done when the browser chat answers list, What is the reorder quantity for SKU-001? (37 units) and Give me a full analysis for SKU-005. (53 units), and the terminal shows the [tool] calls.

Think about it

  1. Step 04: did the LLM's DESIRED_STOCK exactly match the Python check? Why is "close enough" not good enough here?
  2. Step 05: which parts of the RAG answer could only come from the retrieved notes?
  3. Step 06 vs Step 07: one lets the LLM choose the order of tools, the other has a fixed order. Give one advantage of each.
  4. Why does Step 06 have MAX_STEPS? What could happen without it?
  5. In Step 08, the agent only gets the 3 most relevant notes, not all 13. Why not send all of them every time?
  6. SKU-009 (Bluetooth Speaker) has 120 in stock and a desired stock of 119.14. The tool says "no reorder". Would you, as the store manager, still order? What extra information would you want?
