5. Install Custom Skills

Your first real build. You create a throwaway Codex project, send my first build prompt and watch Codex create a whole React site from nothing. While it works, you install the grilling skills we use for the rest of the course. Then you review what Codex changed, run the site and open it in Chrome.

Throwaway project≈ 30–40 minInstalls the /grill skills

What you'll do

  • Add your first Codex project (an empty folder) and send your first real build prompt.
  • Install the four grill skills (grill-me, grilling, grill-with-docs, domain-modeling) with one npx command, and understand what a skill actually is.
  • Find the skills in Codex's / menu and read one of them.
  • Read Codex's summary, review the files it created, run the site with npm run dev and open it in Chrome.

Before you start

  • You finished guides 1–2: Node.js is installed, Codex is set to 5.6 Sol Medium and permissions are Approve for me.
  • This project is a warm-up. We delete it in guide 7, so don't worry if your site looks different from mine. The point is to see the full loop once: prompt → build → review → run.
  • Have both the Codex app and the Terminal app open. Step 4 runs in Terminal while Codex is busy in step 3.
📘 Concept: skills (slash commands)

A skill is a reusable prompt saved as a file, with a name you can call by typing / and the name in the message box. Instead of typing “ask me ten hard questions about my plan before you build anything” every time, you install a skill called grilling once, and from then on /grilling does it. Each skill is a folder containing a SKILL.md file: plain text instructions that Codex reads and follows when you call it. Skills live in ~/.agents/skills on your Mac, which means they are available in every project. They are the only add-on this course uses.

1

Create an empty folder for the throwaway project

Codex needs a folder to work in. We give it a brand-new empty one, so there is nothing to confuse it and nothing of yours it could damage. I keep everything for this course under ~/codex-course, so the throwaway goes there too. Paste into Terminal:

❯Run in TerminalTerminal app · any folder
mkdir -p ~/codex-course/auctionhouse-throwaway
ls -A ~/codex-course/auctionhouse-throwaway | wc -l

Line by line:

  • mkdir -p ~/codex-course/auctionhouse-throwaway creates the folder. -p also creates any missing parent folders and does not complain if the folder already exists.
  • ls -A … | wc -l lists everything in the folder, including hidden files, and counts the lines. It is a quick way to prove the folder is truly empty.
✓ You should see

0: the folder exists and is empty. That is the “blank slate” we start from. Nothing else prints; mkdir is silent when it succeeds.

2

Add the folder as a Codex project

📘 Concept: Codex project

A project in Codex is simply a folder on your Mac that you have given Codex permission to read and edit. Everything Codex does in a chat, reading files, writing code, running commands, happens inside that folder. It cannot wander off into your Documents or your photos. One project can have many chats; the sidebar groups them under the project name. This is also why we made the folder first: Codex wants an existing folder to point at.

  1. In Codex, click New chat at the top of the left sidebar.
  2. Click Choose project (the grey bar just above the message box). A list of projects opens; yours is empty. Click + New project at the bottom of the list.
  3. In the Create project dialog, type the project name below into the name field.
  4. Under Source folders, click Add folders Codex can read and edit. A Finder window opens. Press Cmd+Shift+G (“Go to folder”), paste the folder path below, press Enter, then click Open.
  5. Click Create project.
≡Project nameCreate project → name
auctionhouse throwaway
≡Folder pathFinder → Cmd+Shift+G
~/codex-course/auctionhouse-throwaway

Before you click Create, the dialog shows auctionhouse throwaway as the name with auctionhouse-throwaway listed under Source folders.
After: the sidebar's Projects list has auctionhouse throwaway with “No chats” under it, and the main area asks What should we work on in auctionhouse throwaway?. The bar above the message box shows the project name instead of “Choose project”.

3

Send the first build prompt

Paste my prompt into the message box and press Enter. Read it once before you send it. I am deliberately specific: I name the framework (React), I limit the scope (two routes only), I give a number (six sample auctions), and I ask for three different looks so I can pick one instead of accepting the first design. The more precise the request, the less Codex has to guess, and guesses are where things go wrong.

📘 Concept: route

A route is one address inside a web app. / is the home page; /auction/42 is “the page for auction number 42”. In a React app, a router looks at the address in the browser bar and decides which screen to show. “Two routes” therefore means two screens: the list of auctions, and one auction's detail page. Keeping it to two is how I stop Codex from building a login page, a seller dashboard and a dozen other things nobody asked for.

✦Paste into CodexCodex message box (auctionhouse throwaway)
I would like to build an auction site. it's going to roughly model how other popular auction sites look online.

please use React
keep it to two routes right now:
- Home page with auctions on it as well as some sample auctions (6)
- separate route to actually view the auction

I'd like you to build it with three different looks/themes, have those available on the homepage, and let me click between them
✓ You should see

Your message appears in the chat, and the lines starting with - turn into bullets. A new chat appears under the project in the sidebar with a spinning indicator; after a few seconds it renames itself to something like “Build React auction site”. Codex writes a short opening line similar to “The workspace is empty, so I'm setting this up as a fresh Vite React app…”, and then you see it working: creating files, running commands, thinking. It runs for a few minutes; mine took about 4½ minutes.

💡 Tip

If Codex pauses and asks you to approve a command, for example npm install (which downloads the packages the project needs from the internet), click Approve. Don't sit and watch the spinner: leave this chat working and go straight to step 4 in Terminal. If Codex ever stops before it's done (you see “You stopped…” or it simply goes quiet with no summary), send the single word continue in the same chat and it picks up where it left off.

⚠ Heads up

This is your first real build. Codex reads and writes a lot of text over several minutes on Sol, so expect a noticeable charge on your API bill. Check platform.openai.com → Usage afterwards so you learn what a build like this costs. That number is useful: it tells you what a “build me a site” prompt actually costs, and you will budget better for the rest of the course.

4

Install the grill skills

While Codex builds, switch to the Terminal app and run the command below. It is an interactive installer: it asks you a series of questions. Use the arrow keys to move, Space to tick or untick an item, and Enter to confirm and move to the next question.

❯Run in TerminalTerminal app · any folder
npx skills@latest add schneidenbach/skills
📘 Concept: npx

npm installs packages into a project. npx downloads a package and runs it immediately, without installing it anywhere permanent, which is perfect for one-off tools like this installer. skills@latest means “the newest version of the tool called skills”, and add … tells it which collection of skills to fetch. The first time you run it, npm asks permission to download the tool; that is the “Ok to proceed?” question below.

Answer the questions exactly like this:

  1. “Need to install the following packages… Ok to proceed? (y)” → type y and press Enter.
  2. Select skills to install → use the arrow keys and Space to tick exactly these four: domain-modeling, grill-me, grill-with-docs, grilling. Leave everything else unticked. Press Enter.
  3. Which agents do you want to install to? → just press Enter. The “Universal (.agents/skills)” group is always included, and that is the one Codex reads.
  4. Installation scope → choose Global → Enter. Global means the skills are available in every project on this Mac, not just one folder.
  5. Installation method → Symlink (Recommended) → Enter. A symlink is a shortcut: the skill files are downloaded once and ~/.agents/skills points at them, so updating later is easy.
  6. Proceed with installation? → Yes.
✓ You should see

A “Security Risk Assessments” table where every row says Safe / 0 alerts / Low Risk (the installer scans each skill's text for anything dangerous before installing), then Installed 4 skills, listing ~/.agents/skills/grilling, grill-with-docs, grill-me and domain-modeling, and finally “Done! Review skills before use; they run with full agent permissions.” That last line is a fair warning: a skill is a prompt, and Codex will follow it with the same permissions it has for everything else, so only install skills from sources you trust.

💡 Tip

The list of skills offered may be longer than four, because the collection grows over time. Only the four above matter for this course. Confirm they landed by running ls ~/.agents/skills in Terminal; it should print domain-modeling grill-me grill-with-docs grilling. If you ticked something extra by mistake, it does no harm, but you can delete its folder from ~/.agents/skills.

5

Find the skills in the / menu

Back in Codex, click New chat. It opens inside the same project, and your build keeps running in its own chat; you can see it still spinning in the sidebar. Type the text below in the message box but don't press Enter. We only want to see the menu that pops up.

≡Type in CodexCodex message box (don't press Enter)
/grill
✓ You should see

A menu above the box lists three skills whose names start with “grill”:

  • Grill Me: Sharpen a plan through interview
  • Grilling: Stress-test thinking a round of questions at a time
  • Grill with Docs: Grill a design and write its docs

Delete the text and type just / to see the full list, which also includes Codex's built-in commands (Init, Model, Plan mode, Reasoning, Status…) and the fourth skill, domain-modeling. Built-in commands and your installed skills live in the same menu; that is the whole idea of “custom slash commands”. Clear the box when you're done.

I want you to read one skill, so you see that there is no magic inside. Open the grilling skill in VS Code:

❯Run in TerminalTerminal app · any folder
code ~/.agents/skills/grilling/SKILL.md

It is a page of plain English telling Codex how to behave when you call /grilling: ask questions one round at a time, challenge weak assumptions, do not start building until the plan is solid. We use it for real in guide 8. For now, just notice that a skill is nothing more than a well-written prompt saved in a file.

💡 Tip

If the grill skills don't show up in the / menu, wait until the build in the other chat has finished. Then quit Codex fully (Cmd+Q), reopen it, and try again. Codex scans ~/.agents/skills when it starts, so a restart is sometimes needed after installing.

6

Read Codex's summary when the build finishes

Click the build chat in the sidebar (the one named something like “Build React auction site”). Wait until the spinner stops and the chat shows Worked for … with a time. Then read the summary Codex wrote. Always read the summary: it is Codex telling you what it believes it built, and the first place you catch a misunderstanding.

✓ You should see

A summary similar to:

  • “Built the React auction site with: Homepage featuring six sample auctions · Individual auction routes at /auction/:id · Three switchable themes: Gallery, Modern, and Market · Theme persistence between routes · Responsive desktop and mobile layouts”
  • Key files: App.jsx, styles.css, data.js
  • “Verified with npm run build…” and Run it with: npm run dev
  • A card Edited 6 files +519 -0 with Undo and Review buttons.

Your file names, theme names and numbers will differ. That's normal; every run is a little different.

📘 Concept: /auction/:id and the Edited card

In a route like /auction/:id, the :id part is a placeholder. It means “whatever comes after /auction/ is the id of the auction to show”, so one route serves all six auctions. The Edited 6 files +519 -0 card is Codex's receipt: six files touched, 519 lines added, 0 removed (it is a new project, so nothing existed to remove). Undo reverts everything from this turn; Review shows you the changes line by line. You will see this card after every build in the course.

7

Review what Codex changed

Click Review on the “Edited … files” card. A panel opens on the right showing the changes. At the top of that panel there is a dropdown that reads Last Turn ▾; click it to see the other views, then switch back to Last Turn.

📘 Concept: diff

A diff is the difference between two versions of a file, shown line by line. Lines marked with a green + were added; lines with a red − were removed; unchanged lines are context. Reviewing the diff, rather than the whole file, is how engineers check an AI's work quickly: you look only at what moved. The dropdown's other views (Uncommitted, Unstaged, Staged, Committed, Branch) are different Git slices of the same idea; we use them from guide 15 onwards when we start committing each part.

✓ You should see

A list of new files (index.html, package.json, src/App.jsx, …), each with green + lines, because everything is new. The dropdown offers Last Turn, Uncommitted, Unstaged, Staged, Committed, Branch. I stick with Last Turn here, which means “what this chat just changed”, and I do not read every line of a throwaway. In guide 7, when we build the real app, we read much more carefully.

💡 Tip

The top-right toggle side panel icon also opens Files, Side chat, Browser and Terminal. I use Side chat a lot: it lets me ask “what does this file do?” without adding noise to the main chat that is doing the work. If you don't see Side chat in your version, open a New chat in the same project for side questions instead. The Uncommitted/Staged views need Git, and this throwaway folder is not a Git repo, so they may be empty. That's expected.

8

Run the site

Click the toggle bottom panel icon (left of the two icons at the top-right). The terminal opens, already inside the project folder. Run:

❯Run in TerminalCodex bottom panel (auctionhouse throwaway)
npm run dev
📘 Concept: dev server, localhost and ports

npm run dev runs the “dev” script from package.json, which starts Vite's development server: a small web server on your own Mac that serves the site and reloads the page instantly whenever a file changes. localhost is the address that means “this very computer”. The number after the colon, 5173, is the port: one machine can run many servers at once, and each listens on its own numbered door. Vite's default door is 5173. Later, our backend will listen on a different port, and the database on yet another.

✓ You should see

Vite starts and prints something like VITE v8.x ready in 68 ms and ➜ Local: http://localhost:5173/. The command does not finish and return to the prompt; it keeps running, serving the site, until you stop it with Ctrl+C. That is correct behaviour for a server.

💡 Tip

If you see vite: command not found, Codex didn't install the packages. Run npm install first (it reads package.json and downloads everything listed there into a node_modules folder), then npm run dev again. If the prompt isn't in the project folder, run cd ~/codex-course/auctionhouse-throwaway first; pwd tells you where you are.

Codex has a built-in browser in the side panel, but it does not work with an API-key sign-in, so go straight to Chrome. Copy the address below into the address bar and press Enter.

↗Open in browserChrome
http://localhost:5173
✓ You should see

A polished, very “AI-looking” auction site. In my run, Codex named the site GAVEL, with the tagline “Remarkable objects. Open for bidding.”, luxury lots (a Porsche, an Eames Lounge Chair, a Rolex), a theme switcher at the top-right, and a Choose your viewing style section offering Gallery / Modern / Market. Your names and designs will differ from mine, but the structure (six lots, detail pages, three themes) should match the prompt.

Stuck or got a very different result?

Nothing later depends on this throwaway site, because we delete it in guide 7, so there is no reference copy to catch up from. If the build stopped halfway, send the first message below in the build chat. If the site is broken in the browser, copy the error text from the terminal or from Chrome into the chat and let Codex fix it, or just move on. What does matter is the skills: if step 4 went wrong, run the install again and check the folder.

The second line lists the installed skills folder; you want to see all four names. If a skill is missing, re-run the installer and make sure it is ticked (Space) before you press Enter.

Key takeaways

  • Be prescriptive: say the stack and the shape you want (React, two routes, six sample auctions). Asking for three looks to choose from costs very little extra and gives you a real choice instead of one guess.
  • Skills are custom slash commands: reusable prompts saved as SKILL.md files. They live in ~/.agents/skills, work in every project, and are the only add-on this course uses.
  • Grilling front-loads the thinking: Codex asks you hard questions before it builds. I skipped it here on purpose, because a throwaway is a good place to see what happens without it. From guide 8 we always grill first.
  • After every build: read the summary, open Review → Last Turn to see exactly what changed, then run it and look at it in a real browser. Prompt → build → review → run is the loop for the whole course.
  • npm run dev starts a local dev server on localhost:5173. It keeps running until you stop it; that is normal for any server.
