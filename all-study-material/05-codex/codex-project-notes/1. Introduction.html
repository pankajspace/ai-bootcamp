1. Introduction

One-time setup. Install the tools, get the course repo, and create the practice folder that every later guide works in. Nothing goes into Codex yet.

One-time setup≈ 25–35 minNo Codex prompts yet

What you'll do

  • Check that Git, Node.js, Docker Desktop, VS Code and Microsoft Edge are installed, and install whatever is missing.
  • Download the reference copy of the finished project, so you can always compare your result with a working one, or catch up if you fall behind.
  • Create your own workshop copy that starts exactly where we start in guide 7: only Part 1 built, Parts 2–8 empty.
  • Set Codex to the model and reasoning level we use for the whole course.
  • Understand what is different when you sign in to Codex with an API key instead of a ChatGPT plan.

Before you start

  • You have the Codex app installed on your Mac and you are signed in with your OpenAI API key. That is how I have set this course up. With an API key, every prompt you send is billed to your OpenAI Platform account, so you do not need any ChatGPT subscription.
  • Open the Terminal app (press Cmd+Space, type Terminal, press Enter). Every “Run in Terminal” box in this guide is pasted there.
  • You do not need to know any backend development yet. I explain every tool and every concept the first time we meet it.
📘 Concept: what we are building

Over 26 guides we build one real app: an auction house. Sellers post items, bidders place bids, the highest bid wins when the clock runs out, the winner pays. It sounds simple, but it forces us through every serious backend topic: a database, concurrent users fighting over the same row, real-time updates, background workers, message queues, payments and tracing. We do not write the code by hand. We direct Codex, an AI coding agent, and learn to review and test what it writes. The app is built in eight parts, one folder each, and each part adds one more capability on top of the previous one.

1

Check which tools you already have

Before installing anything, let's see what is already on your Mac. Paste the block below into Terminal and press Enter. Each line asks one tool to print its version number.

❯Run in TerminalTerminal app · any folder
git --version
node --version
npm --version
docker --version
code --version | head -1

What each line checks:

  • git --version — Git tracks every change to the code. We use it to download the course repo and, later, to see exactly what Codex changed.
  • node --version — Node.js runs JavaScript outside the browser. Our backend server and all our tooling run on it.
  • npm --version — npm comes with Node.js. It installs the packages (libraries) a project depends on.
  • docker --version — Docker runs services like the database in isolated containers, so you do not install PostgreSQL directly on your Mac.
  • code --version | head -1 — VS Code is the editor we use to read the code. | head -1 just keeps the first line of its output.
✓ You should see

Five version lines, for example git version 2.x, v22.x.x, 10.x.x, Docker version 2x.x, 1.9x.x.
Node must be v20.19 or newer (v22 LTS is ideal). The frontend of our app is built with Vite 7, which refuses to run on older Node versions.

💡 Tip

Any line that prints command not found means that tool is missing. Note which ones, and install only those in the next step.

2

Install anything that's missing

Install only the tools that printed command not found in Step 1:

  • Node.js 22 LTS: nodejs.org/en/download. The macOS installer (.pkg) is fine. “LTS” means long-term support, the stable line.
  • Docker Desktop: docker.com/products/docker-desktop. Open it once after installing and wait until the bottom-left corner says “Engine running”.
  • Git: run xcode-select --install in Terminal (installs Apple's developer tools, which include Git), or download it from git-scm.com.
  • VS Code: code.visualstudio.com. After installing, open VS Code, press Cmd+Shift+P, type Shell Command: Install 'code' command in PATH and press Enter. That is what makes code work from Terminal.
  • Microsoft Edge: microsoft.com/edge. Required. In guides 11–12 we write automated browser tests (the “bidding war”) that open real Edge windows so you can watch four users bid at once. Keep Chrome too if you prefer it for normal browsing.

If you already use Homebrew (the Mac package manager), this one command installs Node, Git and the GitHub CLI together. You will need the GitHub CLI (gh) in guide 22, so installing it now saves a step later.

❯Optional: Homebrew installTerminal app · only if you use Homebrew
brew install node@22 git gh
✓ You should see

Re-run the Step 1 check. Every tool now prints a version. If a freshly installed tool still says command not found, close Terminal completely (Cmd+Q) and open it again, so it picks up the new PATH.

3

Make sure Docker is running

Our database (PostgreSQL) and, later, Redis, RabbitMQ and Jaeger all run inside Docker. Open Docker Desktop from your Applications folder, wait for it to start, then confirm from Terminal that it is actually running:

❯Run in TerminalTerminal app · any folder
docker info --format 'Docker is running: {{.ServerVersion}}'
📘 Concept: Docker and containers

A container is a lightweight, isolated box that runs one piece of software with everything it needs. Instead of installing PostgreSQL on your Mac and fighting with versions and settings, we tell Docker “run a Postgres container” and it appears in seconds, exactly the same on every learner's machine. When you are done, you stop the container and your Mac is untouched. Docker Desktop is the app that runs these containers; the docker command in Terminal talks to it.

✓ You should see

Docker is running: 2x.x.x

💡 Tip

If you see “Cannot connect to the Docker daemon”, Docker Desktop is not fully started yet. Give it about 20 seconds and run the command again.

4

Download the finished project (reference copy)

The course repo contains the finished auction app with all 8 parts built. We download it once as a reference. Treat this copy as read-only: you will use it to compare your result with a working one, or to catch up if something goes wrong in a later guide. Never work inside it.

❯Run in TerminalTerminal app
mkdir -p ~/codex-course && cd ~/codex-course
git clone https://github.com/schneidenbach/master-dot-dev-codex-course-live.git reference
ls reference

Line by line:

  • mkdir -p ~/codex-course creates a folder called codex-course in your home directory (~ is short for your home folder, /Users/yourname). -p means “don't complain if it already exists”. && cd ~/codex-course then moves into it.
  • git clone … reference downloads the repo and names the folder reference.
  • ls reference lists what is inside, so you can confirm the download worked.
📘 Concept: repository and clone

A repository (repo) is a project folder whose full history is tracked by Git. Cloning downloads a complete copy of that repo, history included, onto your machine. Once cloned, the copy is yours; changes you make locally do not affect the original.

✓ You should see

AGENTS.md README.md docker-compose.yml part-1-foundation … part-8-cross-stack-debugging scripts stripe-service

One folder per part, plus a docker-compose.yml that describes the shared services (database and friends) and a stripe-service folder we use for fake payments in guide 23.

5

Create your practice copy (workshop)

In this course we start with only Part 1 built. Parts 2–8 are empty folders that Codex fills in as we go. The commands below make a second copy of the repo that matches that starting point, with a fresh Git history, so that from guide 7 onwards you can see exactly what Codex changes and nothing else.

❯Run in TerminalTerminal app
cd ~/codex-course
git clone https://github.com/schneidenbach/master-dot-dev-codex-course-live.git workshop
cd workshop
for d in part-[2-8]-*; do rm -rf "$d"; mkdir "$d"; done
rm -rf .git && git init -q && git add -A && git commit -qm "Workshop start: part 1 only"
ls part-1-foundation; ls part-2-create-auction-and-bid | wc -l

Line by line:

  • Clone the repo a second time, this time into a folder called workshop, and move into it.
  • The for loop goes through every folder whose name starts with part-2 up to part-8, deletes it (rm -rf) and recreates it empty (mkdir). Part 1 is left alone.
  • rm -rf .git throws away the downloaded history. git init -q starts a brand-new, empty history. git add -A stages every file and git commit -qm "…" saves them as the first snapshot, named “Workshop start: part 1 only”. The -q flags just keep the output quiet.
  • The last line lists Part 1's files and counts the files in Part 2 (wc -l counts lines, so it prints how many entries ls found).
📘 Concept: commit

A commit is a saved snapshot of the whole project at one moment, with a message describing it. Because our workshop starts with exactly one commit, every file Codex adds or edits later shows up clearly as “changed since the start”. In guides 15 and 16 we use this to review Codex's work and to commit each part as we finish it.

✓ You should see

The first line lists Part 1's files (AGENTS.md CODEX.md GRILL.md README.md package.json server web …). The second line prints 0, meaning Part 2 is empty and ready for Codex.

💡 Tip

You now have two folders:

  • ~/codex-course/reference: the finished project. Read it, compare with it, never edit it.
  • ~/codex-course/workshop: your practice copy. Every later guide works in here.

Set the model we use for the course

Open the Codex app. Look at the bottom-right of the message box: there is a model picker that shows something like “5.6 Terra Medium”. Click it and choose the model and reasoning level below. We use this setting for almost the whole course, and I will tell you clearly whenever we change it.

⚙ Codex settings
ModelGPT-5.6 Sol
ReasoningMedium
ApprovalsApprove for me (shown under the message box)
📘 Concept: model, reasoning level and approvals

The model is the AI brain Codex uses; Sol is the strongest tier, Terra is cheaper and faster, Luna is the smallest. The reasoning level (Low / Medium / High) controls how long the model thinks before answering. More thinking means better results on hard problems, but more tokens and more time. Approvals decide whether Codex may run commands on your machine by itself. “Approve for me” lets it run routine commands (install packages, run tests) without asking you every time, which is what we want for a hands-on course.

✓ You should see

The picker under the message box reads 5.6 Sol Medium.

💡 Tip

If the model list keeps spinning on “Loading models”: quit Codex fully (Cmd+Q) and reopen it. If it still spins, go to platform.openai.com and check that your API key has billing credits and All permissions.

⚠ Heads up

Cost: with an API key you pay per token. Sol is the strongest and most expensive tier. A grilling session or building one slice of the app can each use a lot of tokens. To practise more cheaply, use 5.6 Terra for simple steps and switch to Sol for the big build prompts. Keep an eye on platform.openai.com → Usage while you learn; I show you how to set a spend alert in guide 3.

7

Know what's different with an API-key sign-in

These guides assume you are signed in with an API key. A few Codex features exist only for ChatGPT-plan sign-ins, so I want you to know in advance what you will not see, and what we do instead:

  • Built-in browser preview inside Codex: not available. We open the app in Chrome or Edge ourselves, or ask Codex to drive a browser through Playwright (guide 6 shows how). You lose nothing.
  • Codex cloud and GitHub pull-request reviews by Codex: not available. Local code review with the /review command does work, and that is what we use in guide 16.
  • Everything else the course relies on works: local projects, the terminal panel, skills, AGENTS.md, plan mode, model and reasoning settings, worktrees and Git tools.
✓ You should see

Nothing to run here. Just keep this in mind so nothing surprises you later.

Stuck or got a very different result?

If git clone fails, check your internet connection and that Git is installed (Step 1). If the clone stops halfway, delete the half-downloaded folder and run the step again. If you ever want to start the workshop over from scratch, delete it and repeat Step 5:

❯Run in TerminalTerminal app
rm -rf ~/codex-course/workshop

If VS Code's code command is missing, open VS Code, press Cmd+Shift+P, run “Shell Command: Install 'code' command in PATH”, then reopen Terminal.

Key takeaways

  • We build one auction-house app in vertical slices: one folder per part, Part 1 → Part 8, each adding one capability on top of the last. You will meet this idea again and again.
  • Two copies: reference is the finished project (read-only), workshop is yours. All work happens in workshop.
  • You will mostly work inside the Codex app. Terminal and VS Code are for setup and for reading code.
  • Model 5.6 Sol, reasoning Medium, Approve for me: our default settings. Switch to Terra when you want to save money on simple steps.
  • This course teaches a real engineering workflow and backend fundamentals, not “vibe coding”. You will understand every line Codex writes before you accept it.
