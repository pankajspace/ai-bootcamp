2. Codex Overview

A guided tour of the Codex app. You will find each part of the window, set the permission level, choose the model, effort and speed, and open the built-in terminal once. After this guide, when I say “click the model button” or “open the bottom panel”, you will know exactly what I mean.

App tour≈ 10–15 minNo project needed yet

What you'll do

  • Learn the four areas of the Codex window: left sidebar, main chat, right side panel and bottom terminal.
  • Set permissions to Approve for me, the setting we use for the whole course, and understand what the other two options would do.
  • Change one setting (default file open destination → VS Code) so that any file Codex shows you opens in a proper code editor.
  • Pick the model, effort and speed from the menu under the message box, and learn what each of the three actually controls.
  • Open the bottom terminal panel and the right side panel once, so they are not a surprise when we need them later.

Before you start

  • You finished guide 1: tools are installed, and both ~/codex-course/reference and ~/codex-course/workshop exist on your Mac.
  • Open the Codex app. On some Macs the menu bar at the top of the screen says “ChatGPT” instead of “Codex”. That is normal: Codex ships inside OpenAI's ChatGPT desktop app. Same thing, same screens.
  • Nothing in this guide touches your project folders. You only click around the app and send one tiny test message.
📘 Concept: what a coding agent is

Codex is a coding agent. Strip away the nice interface and every coding agent is the same four things: a loop, an LLM (the language model that reads and writes text), access to your files and access to your command line. The loop works like this: you send a message; the model decides whether to read a file, edit a file or run a command; it does that one action; it looks at the result; it decides the next action; and it repeats until it believes the job is done, then reports back to you. A plain chatbot can only talk. An agent can act on your computer. Everything else you see in the Codex window, the sidebar, the settings, the pet, is convenience built around that loop.

1

Find the four areas of the window

Look at the Codex window and find each of these areas. Do not click anything yet; I only want you to know where things are.

  • Left sidebar: “Codex ▾” at the top, then New chat, Pull requests, Sites, Scheduled, Plugins, and below those three groups: Pinned, Projects and Recents. Think of the sidebar as your history and your folder list. Every conversation you have with Codex is a chat, and old chats show up under Recents. A project is a folder on your Mac that Codex is allowed to read and edit; your projects are listed under Projects.
  • Main window: the big “What should we build?” area with the message box at the bottom. This is where you type prompts and where Codex's answers, file edits and command output appear. You will spend most of the course looking at this area.
  • Top-right corner: two small square icons. The left one toggles the bottom panel, which is a terminal. The right one toggles the right side panel. We open both in steps 8 and 9.
  • Pet: a little animated creature somewhere near the top-right. It is just for fun and does nothing.
✓ You should see

“What should we build?” in the middle of the window, a Choose project button just above the message box, and the message box itself showing the placeholder text Do anything. “Choose project” being there means no folder is selected yet, which is exactly where we want to be in this guide.

💡 Tip

Your Projects list is empty for now. You add your first project in guide 5. If you don't see a pet, that's fine; pets are not needed for anything in this course. If your sidebar has one or two items more or fewer than my list, that is just a version difference. The four areas are what matter.

2

Open the profile menu (bottom-left)

Click your name at the bottom-left of the sidebar. This is the account menu. We come back here in step 5 for Settings, so I want you to know where it is.

📘 Concept: usage and tokens

Everything you send to Codex, and everything it writes back, is measured in tokens. A token is a piece of a word; on average, 100 tokens is about 75 English words. Code uses more tokens than prose because of all the brackets and symbols. With an API key you pay per token, both for what goes in (your prompt plus the files Codex reads) and for what comes out (the answer, the code it writes, and the hidden “thinking” it does before answering). This is why a small “hello” costs almost nothing and a “build the whole feature” prompt can cost a lot.

✓ You should see

A small menu opens with Usage, Hide pet, Invite a friend, Settings (shortcut ⌘,) and Log out. The Usage line is designed for ChatGPT plans, where it shows a percentage of the plan left (for example “78% left”).

💡 Tip

You signed in with an API key, so your Usage line may look different or show no percentage at all. Your real spend is at platform.openai.com/usage. Bookmark it and check it after each of the bigger build guides. In guide 3 I show you how to set a spending alert there so you never get a surprise.

3

Type in the message box

Click the message box (the one that says “Do anything”) and type the text below. There is no project selected, so Codex cannot touch any files; it will simply chat. I want you to press Enter and actually send it. It is the cheapest possible test that your API key works, and I would rather you find a key problem now than in the middle of guide 7 when Codex is halfway through building something.

✦Paste into CodexCodex message box · no project selected
hello world

Two keyboard habits to learn right now, because you will use them in every guide: Enter sends the message. Shift+Enter adds a new line inside the message without sending, which you need when a prompt has several lines. All the prompts in these guides have a Copy button, so you paste them in one go and then press Enter.

✓ You should see

The text appears in the box. After you send it, your message shows at the top of the chat and Codex replies with a short greeting within a few seconds. That greeting proves three things at once: the app can reach OpenAI, your key is accepted, and your account has credits to spend.

💡 Tip

If sending shows an authentication or billing error, go to platform.openai.com and check two things: the key is still active (not revoked) and the account has credits. The key needs “All” permissions, and the account needs prepaid credit; how much the course costs you depends on how many big builds you run, which is why guide 3 sets a budget.

4

Set permissions to “Approve for me”

Under the message box, on the left, there is a small shield-style button. It shows the current permission level, for example “Approve for me” or “Ask for approval”. Click it. A menu opens with the question “How should ChatGPT actions be approved?” and three options. Choose Approve for me.

📘 Concept: approvals (permissions)

Remember that Codex can run commands on your Mac: install packages, start a server, run tests, create and delete files. The approval level decides how much it has to ask you before doing these things. Ask for approval means every single command stops and waits for your click. Approve for me means routine commands inside your project run on their own, and Codex only stops to ask when it detects something potentially unsafe, like touching files outside the project or reaching out to the internet. Full access means it never asks. Think of it as how much you trust a new intern: watch every keystroke, let them work and check in on the risky bits, or hand them the keys to everything.

⚙ Codex settings
ApprovalsApprove for me
✓ You should see

Three options:

  • Ask for approval: always ask to edit external files and use the internet
  • Approve for me: only ask for actions detected as potentially unsafe
  • Full access: unrestricted access to the internet and any file on your computer (shown in red)

After you choose, a ✓ sits next to Approve for me, and the button under the message box now reads “Approve for me”.

⚠ Heads up

Don't pick Full access on a computer that has your work or personal files on it. The only place it is acceptable is a spare machine that holds nothing important. “Ask for approval” is safe but very slow: in guide 7 Codex runs dozens of commands while building the first version of our app, and you would be clicking Approve thirty or forty times. Approve for me is the practical middle: the course is designed around it.

5

Set VS Code as the default file opener

When Codex edits files, it shows their names in its answer and in “Edited N files” cards. Clicking a file name opens it, and this setting decides in which app. We want VS Code, because it shows syntax colours, the folder tree and, later, the Git changes side by side. Do the following:

  1. Open Settings: click your name at the bottom-left → Settings, or press ⌘, (Command and comma together).
  2. You land on the General page. Scroll down until you see the section also called General.
  3. Find Default file open destination. It is a dropdown. Open it and pick VS Code.
  4. Click ← Back to app at the top-left when you're done. The setting is saved automatically; there is no Save button.
✓ You should see

Default file open destination shows VS Code. From now on, clicking any file name in a Codex answer opens that file in VS Code, in the correct folder, ready for you to read. We rely on this from guide 7 onwards every time I ask you to “open the file and read what Codex wrote”.

💡 Tip

While you're in Settings, glance at the left list so you know what is there: General, Profile, Appearance, Pets, Keyboard shortcuts, Usage & billing, and under Integrations Plugins and Browser. Leave everything on its default. You may also see a place for MCP servers: these are add-ons that give the agent extra tools, such as talking to an external service. This course uses no MCP servers; Codex's built-in file and terminal access is all we need, so ignore that part completely.

6

Optional: pick a pet

This one is purely for fun and you can skip it. In Settings, click Pets in the left list. You see a small gallery of creatures. Click Select next to one you like, then click ← Back to app.

✓ You should see

Your pet appears in the top-right of the window and moves around a little while Codex works. It has no effect on anything Codex does.

💡 Tip

If you don't see Pets in your Codex version, skip this step and tick it Done anyway. Nothing later depends on it. If the pet distracts you, the profile menu from step 2 has a Hide pet option.

7

Pick the model, effort and speed

Under the message box, on the right, there is the model button. It reads something like “5.6 Sol Medium ▾”, possibly with a ⚡ in front. Click it. A small menu opens with three rows: Model, Effort, Speed. Hover your mouse over each row and a list opens out to the side. Set them like this:

  • Model → 5.6 Sol. The list is 5.6 Sol, 5.6 Terra, 5.6 Luna, 5.5, 5.4, 5.4 Mini, 5.3 Codex Spark. They are ordered from most to least powerful. My rule for serious work: use the top model. A weaker model saves a little money and then costs you an hour of debugging.
  • Effort → Medium. The choices are Light, Medium, High, Extra High, Ultra. We use Medium for almost the whole course. It is a good balance of intelligence and speed, and guide 3 is entirely about when to move up or down.
  • Speed → Standard. The other choice, Fast, is described as “1.5x speed, more usage”. I keep you on Standard; see the warning below.
📘 Concept: model vs effort vs speed

These three are easy to mix up. The model is which brain you are using; a bigger model knows more and makes fewer mistakes. Effort (also called reasoning level) is how long that brain is allowed to think before it acts. More effort means more hidden reasoning tokens, which gives better answers on hard problems but costs more and takes longer. Speed does not change the answer at all; it only changes how quickly the tokens stream back to you, and Fast bills you extra for that. So: model = quality ceiling, effort = how hard it tries, speed = how long you wait.

✓ You should see

Click away from the menu to close it. The button now reads 5.6 Sol Medium. If there is a ⚡ in front of the label, Fast is still on; open the menu again and switch Speed to Standard, and the ⚡ disappears.

Open the terminal panel at the bottom

Click the left of the two icons in the top-right corner (toggle bottom panel). A terminal opens along the bottom of the Codex window. Click inside it, paste the command below and press Enter.

❯Run in TerminalCodex bottom panel
pwd
📘 Concept: terminal, prompt and pwd

A terminal is a text window where you type a command, press Enter, and the computer answers in text. The line that waits for your input is called the prompt. A Mac prompt looks like yourname@Your-MacBook / %: your username, then your Mac's name, then the folder you are currently “standing in”, then % meaning “ready, type something”. pwd stands for print working directory: it prints the full path of that current folder. A lone / is the very top of your disk. Whenever you are unsure which folder a terminal is in, type pwd. It is the first thing I do in any terminal I open.

✓ You should see

A terminal tab at the bottom with your normal Mac prompt, something like yourname@Your-MacBook / %. After pwd, one line with a folder path, for example / or /Users/yourname. Later in the course we use this panel to run commands and start servers without leaving Codex, and the Codex agent itself uses the same kind of terminal when it runs commands for you.

💡 Tip

Click the same icon again to hide the panel. You can also keep using the separate Terminal app you used in guide 1; both work exactly the same. The only difference is the starting folder: the Terminal app starts in your home folder, while this panel starts in the current project folder once one is selected. When a copy block in these guides says “Codex bottom panel”, I mean this one.

9

Look at the right side panel

Click the right of the two icons in the top-right corner (toggle side panel). A panel opens on the right edge of the window. Have a look at what it offers, then close it again.

✓ You should see

A panel on the right with options like Browser and Terminal. The Browser option is a small web browser inside Codex, meant for previewing the app you are building. I rarely use it: a real browser window is bigger, you can resize it, open developer tools, and keep it on a second screen while Codex works.

💡 Tip

The built-in Browser needs a ChatGPT sign-in, so it will not work with your API key. That's fine and you lose nothing. Whenever a step needs to look at the running app, the guides have you open the page in Chrome or Edge yourself, using the “Open in browser” copy blocks. Click the icon again to close the panel.

Stuck or got a very different result?

If the model list keeps spinning on “Loading models”, quit Codex completely (Cmd+Q, not just the red close button) and open it again. If it still spins, your API key is probably missing permissions or credits; check both on platform.openai.com.

If your window looks different from my description (different item names in the sidebar, no Speed row, no Pets page), that is a version difference and not a problem. Find the four areas from step 1, the shield button and the model button under the message box, and the two toggle icons at the top-right. Those are the only things the rest of the course depends on.

If the terminal panel does not open, or opens blank, close it with the same icon, wait two seconds and open it again. As a fallback, every terminal command in this course also works in the normal Terminal app.

Key takeaways

  • Every coding agent, Codex included, is a loop + an LLM + file-system access + command-line access. You could write a basic one in a few hundred lines of code. The real skill is in how you direct it, which is what the rest of this course teaches.
  • We do the whole course in the Codex desktop app, not the command-line version. The ideas (prompts, skills, plan mode, AGENTS.md) are the same in both, so nothing you learn is wasted if you switch later.
  • Course defaults: 5.6 Sol, Medium effort, Standard speed, Approve for me. Use the top model, keep effort at Medium unless I say otherwise, and never choose Full access on a machine you care about.
  • Model is which brain, effort is how long it thinks, speed is how long you wait. Only the first two change the quality of the answer.
  • With an API key, the built-in browser preview is not available. We open the app in Chrome or Edge ourselves, and that is actually the better habit.
